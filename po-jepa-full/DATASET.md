# PO-JEPA 可调物理基准（v7，v8 扩展中）

一个可生成、可调节的“画面 + 动作 + 真值物理状态”数据集。每条轨迹是 33 帧 256×256 RGB 画面（4 fps，0.25 s 一帧）、32 个 tick 的二维动作，以及生成画面用的隐藏物理状态（长时程调节项 `horizon` 可延长到 129 帧；时间采样调节项可以改帧率、帧时间抖动、曝光和控制切换时刻；空间采样调节项可以改输出分辨率、缩小、相机平移和漂移）。仿真数据的价值在于有真值方程和真值状态：可以检验模型学到的是不是正确的物理演化，这一点真实数据做不到。

数据集由三部分决定：**场景 × 调节项 × 条数**。写法是 `系统[~调节项]:条数`，例如：

| 写法 | 含义 |
|---|---|
| `double_well:2000` | v6 的双势阱（基础场景，与 v6 逐位一致） |
| `double_well~axes=x,gain=2:2000` | 控制增益 2，只能推 x 方向（欠驱动） |
| `landscape~shape=ring:2000` | 势能地形族里的环形槽 |
| `van_der_pol~background=checker,color=white,mu=1:2000` | 换物理参数和外观 |
| `pendulum~horizon=128:2000` | 129 帧的长时程轨迹（测试段就是长时程测试集） |
| `double_well~fps=8:2000` | 同一批轨迹按 8 fps 取 65 帧（整 tick 的帧与 4 fps 逐位相同；帧率分布外测试） |
| `push~switch_offset=0.5:2000` | 动作在两帧之间切换（段边界挪半个 tick，取值不变） |

调节项的完整定义和取值范围见 `src/po_jepa/variants.py`。仿真与渲染见 `src/po_jepa/systems.py`；v8 新加的 `gray_scott`、`push` 的物理与渲染在 `src/po_jepa/new_systems.py`（公式和参数范围的依据见 `docs/segments/S20a.md` §2）；五个二阶场景在 `src/po_jepa/second_order.py`（`docs/segments/S23a.md` §3，登记见 `S23b.md`）。

## 场景

前 7 个场景是一阶系统：画面里能看到决定未来的全部状态，因为 v7 的模型只看当前一帧（`occluders` 调节项有意破坏这一点，见下）。

后 5 个是二阶场景（S23a 物理和渲染，S23b 登记）：画面只给位置，速度要由相邻两帧给出。数据集照样是 33 帧（tick 0…32），编码、缓存、训练的入口不变；每条轨迹另外多仿真、多画 t = −1 一帧（初值在 t = −1 抽，零动作预跑一个 tick 到 t = 0），由 `systems.get().frames_with_prev()` 给出 34 帧，留给两帧（pair）编码。pair 编码怎么接要等 S22 两帧 tubelet 探针（`tools/tubelet_probe.py`，定义和判据见 `docs/segments/S22.md`）的结果；在那之前用单帧编码时，模型看不到速度。

| 场景 | 方程 | 画面 | 隐藏状态维数 |
|---|---|---|---|
| `double_well` | dx/dt = x − x³ − c·y + tilt + u_x，dy/dt = −y − c·x + u_y（c = 0.25） | 一个光点 | 2 |
| `van_der_pol` | dx/dt = v + u_x，dv/dt = μ(1 − x²)v − x + u_y（μ = 0.5） | 相平面上的一个光点 | 2 |
| `multi_particle` | n 个过阻尼粒子，两两软排斥加简谐外势，动作只推第 0 个（n = 3） | n 个彩色光点 | 2n |
| `advection_diffusion` | ∂c/∂t = D∇²c − w·∇c，w = flow·u（周期域，傅里叶精确解） | 浓度热图 | 256（16×16 池化） |
| `landscape` | dq/dt = −depth·∇V(q) + u，V 可选 4 种地形 | 光点和地形底图 | 2 |
| `gray_scott` | Gray–Scott 反应扩散 ∂U/∂t = D_u∇²U − UV² + F(1−U)，∂V/∂t = D_v∇²V + UV² − (F+k)V + a·G(x−p)(1−V)，注入点 dp/dt = 0.4·u（周期域） | U、V 两色叠加的浓度图和注入点圆环 | 514（U、V 各 16×16 池化，加注入点） |
| `push` | 准静态推方块：推杆 dc/dt = 2u − f，方块按椭圆极限面和库仑静摩擦阈值滑动、转动，可加坡面 | 方块（带朝向标记）和推杆光点 | 5 |
| `pendulum` | θ̈ = −(g/L) sin θ − γθ̇ + 4(u_x cos θ + u_y sin θ)（二维力取切向分量） | 支点、摆杆和摆锤光点 | 2（θ, θ̇） |
| `bouncing_balls` | 方盒里 n 个球，dv/dt = −βv + [i = 0]·1.5u，球与墙、球与球按恢复系数碰撞（事件驱动） | 方框和 n 个彩色圆盘 | 4n（位置、速度；n = 3） |
| `wave` | 周期域 u_tt = c²∇²u − γu_t + load·c²∇²B(x − p)，激振源 dp/dt = 0.4·u（傅里叶精确传播子） | 正负两色的位移场和激振源圆环 | 514（u、u_t 各 16×16 池化，加激振源） |
| `cart_pole` | 小车倒立摆的拉格朗日方程，只受水平推力 F = 1.5u_x（u_y 不起作用），轨道两端有缓冲 | 轨道、小车、摆杆和摆锤光点 | 4（x, ẋ, θ, θ̇） |
| `spring_chain` | 两端固定的线性弹簧链，d̈_i = −k(2d_i − d_{i−1} − d_{i+1}) − γḋ_i + [i = 0]·1.5u（矩阵指数精确推进） | 墙、弹簧线和 n 个彩色光点 | 4n（位置、速度；n = 4） |

`landscape` 的 4 种地形：

- `multi_well`：四个势阱。
- `ring`：环形槽。
- `periodic`：周期势阱阵列。
- `obstacles`：三个障碍物。

规则：

- **配对**：调节项不改变初始状态和动作的随机种子；只有改动作抽样的 `axes`、`segments`、`zero`、`policy` 例外。所以同一编号的轨迹在不同调节项下可以逐条配对比较。`policy` 只换非零段的取值，段的边界和零动作段与 random 相同。
- **随机流**：每条轨迹按用途分流，0 初值、1 动作、2 预处理、3 静止干扰光点、4 像素噪声、5 执行噪声、6 过程噪声、7 遮挡块、8 会动的干扰光点、9 采集策略、10 帧时间抖动、11 tick 内部帧的像素噪声、12 相机。加调节项只会用到新的流，不改动已有流。
- **反事实**：过程噪声按“轨迹 + 绝对 tick”预先抽好，从任意 tick 出发的反事实仿真用同一份噪声，只换动作。
- **基础场景不变**：调节项为空时走原实现，与 v6 和 v7 试跑逐位一致，有单元测试保证。只改观察的调节项，隐藏状态也和基础场景逐位相同。
- **软墙**：可调版本在画面边缘有一圈软墙，增益或参数调大时小球也不会跑出画面。基础场景不加软墙。
- **长时程是前缀延长**：`horizon` 不用新的随机流，动作、执行噪声、过程噪声、像素噪声、会动的干扰光点都按 tick 顺序从各自的流接着抽。所以 `horizon=128` 的一条轨迹，前 32 个 tick 的动作和前 33 帧画面与同编号、其余调节项相同的 33 帧轨迹逐位相同，只是跨过第 32 个 tick 的那一段动作不再被截断。基础场景的 v7 场景走原实现、长时程走可调实现，画面同样逐位相同（`advection_diffusion` 的隐藏状态差约 1e-16）。
- **时间采样**（S24b，`src/po_jepa/timing.py`）：物理仍按 tick 推进（主链，与原实现逐位相同）；tick 内部时刻的状态从主链上之前最近的点出发，沿该场景生产用的子步网格推进，最后不足一个子步的一截用同一格式走一个短步（精确解的场景按时长直接推进）。所以 `fps` 只是同一条轨迹的子采样或加密，同一时刻的帧与取了哪些别的时刻无关。整 tick 的帧用随机流 4 那个 tick 的像素噪声；tick 内部的帧用随机流 11 按帧号另起。二阶场景的 `frames_with_prev()` 前一帧在 t = −4/fps tick（预跑的零动作 tick 内部；`fps=2` 时取不到，报错）。
- **空间采样**（S24c，`src/po_jepa/camera.py`）：相机是“画布”（原来 256×256 画面的坐标系）上一个轴对齐的正方形视野，各画图函数在视野的输出像素中心上取值（原生渲染）：光点、线段、圆盘、方块直接求值，抗锯齿过渡宽度取 max(1, 输出像素边长) 个画布像素；背景纹理、遮挡块和画布边按输出像素面积精确平均（网格线 1 个画布像素宽，点采样会整条漏掉）；场（`advection_diffusion`、`gray_scott`、`wave`）在格点之间周期双线性插值；`gray_scott`、`wave` 的 1 像素宽圆环标记在输出像素大于画布像素时按面积平均加宽。只改画面：物理、动作、隐藏状态与不带空间采样的同编号轨迹逐位相同。帧的生成走时间采样的同一条路径，所以能和 `horizon`、`fps`、`exposure` 等组合（曝光窗口里每个时刻用自己的相机位置）。像素噪声按输出分辨率抽（流 4，[R,R,3] 一块）。
- **新场景**：`gray_scott`、`push` 没有 v6 原实现要保持，基础场景和有调节项时走同一套代码。它们的随机流序号是 5、6（追加在 `datasets.SYSTEMS` 末尾），v7 的 5 个场景的随机流不变。二阶场景同样，序号 7–11（`pendulum`、`bouncing_balls`、`wave`、`cart_pole`、`spring_chain`）。

## 生成与划分

- **划分**：按编号连续切，80% 训练、10% 验证、10% 测试，单位是完整轨迹。
- **条数**：可选 40、200、500、2000。
- **变体测试集**：只编码测试段（`encode_v7.py --splits test`），编号和基础场景的测试段一一对应。
- **时间采样测试集**（S24b 生成，S25d 接入）：`<场景>~<测试项>:2000` 的测试段，与主实验测试段同编号、同物理（`switch_offset` 只挪下达动作的段边界）。测试项是 `protocols.TIMING_TESTS`：`fps=2`、`fps=8`、`fps=16`、`jitter=0.4`、`exposure=1`、`switch_offset=0.5`。`encode_v7.py --variant … --splits test` 只编码测试段，帧数 32·fps/4 + 1（17/33/65/129），manifest 记每帧的实际时刻 `time_ticks`，`switch_offset` 的动作记成 1/4 tick 为单位的 `starts_subticks`/`ends_subticks`；读取是 `runtime/timing_cache.py`（`cache.py` 不改，`cache.read_window` 和 `run.py transfer` 都不收这种缓存）。`tools/timing_eval.py` 用 4 fps 基础场景上训练好的模型按帧评测：从主实验的测试起点所在的帧往后预测 n = 1、2、3、4、8、12 帧（时长是两帧的实际时刻差），一次直接预测和逐帧组合预测离真实特征的 JEPA 距离、两者之差；PO-JEPA、Transformer 直接收非整数时长和 tick 内部的切换时刻，V-JEPA 2-AC 按 tick 步进（动作取每个 tick 的平均，非整数时长在相邻两步之间线性插值），另记“一帧算一步、动作取帧间平均”的误差。任务表 `make_v8_jobs.py --stage timing`。时间采样不和 `horizon` ≠ 32 一起接，探针和规划仍拒绝时间采样。
- **空间采样测试集**（S24c 生成，S25e 接入）：`<场景>~<测试项>:2000` 的测试段，与主实验测试段同编号、同物理、同动作，只有画面不同（分辨率和相机分布外）。测试项是 `protocols.SPACE_TESTS`：`resolution=192`、`resolution=320`、`resolution=384`、`zoom=0.75`、`pan=1,zoom=0.75`、`drift=0.5,pan=1,zoom=0.75`（相机三项都在 zoom=0.75 上叠）。`encode_v7.py --variant … --splits test` 只编码测试段，每条 33 帧，按原生分辨率编码（`po_jepa.native_encoder`：预处理输出 R×R、冻结编码器输入 R×R，不缩放回 256；上游 RoPE 的位置是整数 0…R/16−1），特征网格 R/16（12/16/20/24，384 时 float16 每条约 53 MB）；manifest 的 grid 是 [R/16, R/16]、多一个 `space` 记录，预处理记录和摘要是原生分辨率版，所以 `cache.read_window` 和 `run.py transfer` 都不收这种缓存，读取是 `runtime/space_cache.py`（`cache.py` 不改）。`tools/space_eval.py` 用基础场景上训练好的模型在主实验的测试窗口（起点 s、时长 1、2、3、4、8、12 tick）上直接预测：模型直接吃 R/16 × R/16 的原生特征（PO-JEPA 在这个网格上建图求模态，Transformer 的位置嵌入是归一化坐标的线性函数，V-JEPA 2-AC 用官方 RoPE 按 16/G 缩放位置），记空间采样测试集上的 JEPA 距离、基础测试集同一窗口上的 JEPA 距离、两者之差。任务表 `make_v8_jobs.py --stage space`。空间采样不和 `horizon` ≠ 32、时间采样一起接，探针和规划仍拒绝空间采样。
- **长时程测试集**（S24a）：`<场景>~horizon=128:2000` 的测试段（编号 1800–1999，每类 200 条、129 帧），就是主实验 2000 条测试段的延长。S25c 接上了编码和滚动评测：`encode_v7.py --variant horizon=128 --splits test` 只编码测试段、整条 129 帧都存（float16 每条约 93 MB，每类约 19 GB；按 33 帧一批送进编码器，前 33 帧的特征和主实验缓存相同）；`tools/long_rollout.py` 用基础场景上训练好的模型从 tick 0 滚：T = 16、24、32、48、64 时一次直接预测和每 8 步一段的组合预测离真实特征的 JEPA 距离、两者之差，以及 8 步滚动每隔 8 个 tick 的误差曲线（到 128）；任务表 `make_v8_jobs.py --stage long`。长时程缓存只用来评测（训练、`cache.read_window`、`run.py transfer` 都不收）。动作探针和规划遇到 `horizon` ≠ 32 仍直接报错。
- **编码**：冻结的 V-JEPA 2 ViT-g/16，权重 SHA 67129f…，上游提交 204698b，和 v3 起一直用的是同一套预处理。特征存 float16，每条约 24 MB。
- **可追溯**：每条轨迹的清单里记录场景、调节项、动作、每帧画面的 SHA、随机种子和生成代码的 SHA。

## 已知局限

- 模型只看单帧；二阶场景已登记，探针、规划、评测协议也接上了（S25a），但两帧（pair）编码要等 S22 探针结果，单帧编码时看不到速度；v8 任务表默认不排二阶场景。
- `process_noise` 只用于粒子类 ODE 场景；`policy` 不用于场方程（`advection_diffusion` 的动作是整场流速，`gray_scott` 是注入点速度，没有要推到目标的受控点），也不用于二阶场景（动作是力，`policy=goal` 的开环推算按“动作 ∝ 受控点速度”做，对它们不成立）。
- `cart_pole` 只受水平推力，`axes=y` 等于没有控制，不接受。
- `policy=goal` 是开环推算，不知道执行时的增益、延迟、噪声、饱和和场景的动力学，所以并不总能到目标；它的作用是让动作更多地作用在受控物体上（`push` 上推动方块的轨迹比例明显高于 random，实测见 `docs/segments/S21a.md` §4）。
- `gray_scott`、`push` 在 v8 的任务表（`tools/make_v8_jobs.py`）里，不在 v7 的任务表里。它们的真值规划参照每个 tick 的仿真比粒子类场景贵 10–20 倍，v8 任务表把它们的 `--oracle-samples` 降到 16（`gray_scott`）和 32（`push`）。
- 只画部分帧时（动作探针、规划），像素噪声按 tick 取整条轨迹同一份噪声（S21b 起）；以前单帧重画用的是第 0 帧的噪声。
- `push` 在 v6 的随机动作下，大约三分之一的轨迹真正推动了方块，动作的作用偏弱。
- 动作统一是二维，范围 [−0.5, 0.5]²。
- 长时程（`horizon` 64、128）只接了编码和滚动评测（S25c），动作探针和规划没接；时间采样（`fps`、`jitter`、`exposure`、`switch_offset`）只接了测试段的编码和按帧评测（S25d），不进训练、探针和规划，也不和长时程组合。控制周期仍是 0.25 s（`switch_offset` 只挪切换时刻）。空间采样（`resolution`、`zoom`、`pan`、`drift`）只接了测试段的编码和评测（S25e），同样不进训练、探针和规划，也不和长时程、时间采样组合；不同分辨率下 V-JEPA 2 的特征本身不同（不是同一组 token 的重采样），所以空间采样的误差差量的是“冻结编码器 + 模型”整条链的退化。
- 空间采样只缩小、不放大（放大会把画面边缘的物体切掉，违反“画面能看全状态”）；相机只平移、不旋转。光点和细线是点采样（光点 σ ≥ 3 画布像素，最大输出像素 2.7 画布像素）；场是格点之间的双线性插值，所以 `gray_scott`、`wave` 在相机里即使是 256、zoom 1 的视野也不是原来的 2×2 块复制（默认值不经过相机，逐位不变）。
- 曝光是窗口内有限个时刻的平均（间隔 ≤ 1/8 tick），快速运动时能看到分立的残影，不是连续积分；窗口早于轨迹起点的部分取起点。
- 带过程噪声的场景，tick 内部不在子步网格上的那一截短步，噪声取该子步布朗增量的线性插值（布朗桥的条件均值），不另抽随机数。
- 画面是合成的简单图形，和真实视频有差距。真实数据（DROID）放在下一阶段。

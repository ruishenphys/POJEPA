# PO-JEPA 仿真补跑说明

这份说明写给帮忙跑实验的同学。v7 的正式运行全部跑完以后，在**同一台两卡机器、同一个工作目录**里再补跑一批实验。流程和 v7 一样：**准备一次 → 试跑 → 正式和变体 → D3 → 传回结果**，每一步只要复制几条命令，**不需要改任何代码或配置，不需要装新包，也不需要重新编码特征**（补跑直接读 v7 编好的特征、训练好的模型和标定）。

| | 试跑 | 正式和变体 | D3 |
|---|---|---|---|
| 内容 | 5 个场景 × 200 条轨迹，2000 步，1 个种子，95 条任务 | 5 个场景 × 2000 条轨迹，10000 步，3 个种子，255 + 176 条任务 | 官方规模 AC 的规划重跑，5 条任务 |
| 两张 RTX PRO 6000 大约要 | 半天 | 2–3 天 | 7.5 小时 |
| 在哪个目录跑 | `full-model/po-jepa-full` | `full-model/po-jepa-full` | `po-jepa`（v7 的目录） |

时间是估算，以实际为准（试跑结束后 Jerry 会按实测时间更新）。全程都用这两张卡。

## 一、准备（只做一次）

1. **等 v7 跑完。** v7 的 `jobs-full.txt` 和 `jobs-variants.txt` 都要打印过“全部完成。”。补跑要读 v7 的 `features-v7/`、`results-v7/`、`po-jepa/configs/calibration/`，还有 v7 试跑用的 v6 双势阱特征目录（v7 交接说明里 `V6=` 写的那个绝对路径，在你原来的 v6 工作目录里），这些都不要删、不要改。
2. **环境和 v7 相同**，先激活：

   ```bash
   conda activate pojepa
   ```

3. **取补跑的代码。** 在工作目录（就是 v7 时放 `po-jepa/`、`vjepa2/`、`checkpoints/` 的那个目录）里执行：

   ```bash
   git clone -b full-model https://github.com/ruishenphys/POJEPA.git full-model
   ```

   做完后工作目录是这样的（`results-addon/`、`logs-addon/` 会在运行时自动生成）：

   ```
   工作目录/
     po-jepa/                 ← v7 的代码（不动）；只有 D3 在这里跑
     full-model/po-jepa-full/ ← 补跑的命令（D3 以外）都在这个目录里执行
     vjepa2/  checkpoints/
     features-v7/  results-v7/  logs-v7/   ← v7 的产物（补跑只读）
   ```

   v6 的双势阱特征（`$V6`）不在这里，在你原来的 v6 工作目录里；v7 试跑读过它，补跑试跑也读（只读）。

## 二、试跑（约半天）

```bash
cd full-model/po-jepa-full
V6=<v6 特征目录的绝对路径>        # 和 v7 交接说明里的 V6= 那一行完全相同
grep -- '--system double_well ' ../../po-jepa/jobs-pilot.txt | grep -m1 -o -- '--features-root [^ ]*'   # 应打印 --features-root 和同一个路径
python tools/make_addon_jobs.py --stage pilot --v6-features "$V6" > jobs-addon-pilot.txt
python tools/run_jobs.py jobs-addon-pilot.txt --gpus 0,1
```

第二条命令会自动把任务分给两张卡，一段段跑完：先导入 v7 的标定并核对 v7 的产物（A0），再补跑标定（C）、检查（C2），然后训练和评测（D、D4），最后汇总（E）。屏幕上显示每条任务的开始、完成和用时，每条任务的详细输出存在 `../../logs-addon/jobs-addon-pilot/`。试跑用的是 v7 **试跑**的结果，5 个场景都跑。

`--v6-features` 要给 **v7 试跑时 `make_v7_jobs.py --stage pilot --v6-features "$V6"` 用的同一个绝对路径**（试跑的双势阱读 v6 的特征，补跑必须读同一份）：`V6=` 照抄 v7 交接说明里那一行；记不清的话，上面的 `grep` 会从 v7 的 `jobs-pilot.txt` 里双势阱那几行的 `--features-root` 把它找出来，两者必须相同。**不要用 `po-jepa/features/` 或 `full-model/features/`**：git 克隆下来的这两个 `features/` 只有提交进仓库的说明文件（`report.json`、`COMPLETE.json`、`registration.json`、`0000/manifest.json`），没有任何 `raw_z.npy`，不是特征。不给这个参数会报“试跑必须给 --v6-features”，写成相对路径会报“要写绝对路径”；给错了目录，A0 的 preflight 会报错停下（只有说明文件的目录报的是 `缺 COMPLETE.json、manifest.json 或 raw_z.npy`），不会白跑。v7 交接说明里对 `$V6` 做的几项检查（`report.json` 的 SHA、200 个轨迹目录、`raw_z.npy`）这里不用手动重做，A0 的 preflight 会做，而且更严。

跑的时间长，建议放在 `tmux` 或 `screen` 里，断开 SSH 也不会停。

- 最后打印 **“全部完成。”**：试跑通过，直接开始第三步。同时把试跑结果打包发给 Jerry（见第六节），不用等他回复。
- 打印 **“有任务失败，已停下”**：把结果打包发给 Jerry（见第六节），**先不要开始正式运行**。等回复的时候可以先跑第四节的 D3。

## 三、正式和变体（约 2–3 天）

还是在 `full-model/po-jepa-full` 里：

```bash
python tools/make_addon_jobs.py --stage full > jobs-addon-full.txt
python tools/make_addon_jobs.py --stage variants > jobs-addon-variants.txt
python tools/run_jobs.py jobs-addon-full.txt --gpus 0,1 && python tools/run_jobs.py jobs-addon-variants.txt --gpus 0,1
```

`jobs-addon-full.txt` 是主实验，`jobs-addon-variants.txt` 用主实验训练好的新模型做分布外评测和规划。`jobs-addon-full.txt` 跑完时先把结果发给 Jerry 一次，不用停下来等。

## 四、D3（约 7.5 小时）

D3 用 **v7 目录里原样的代码**重跑官方规模 AC 的规划。它只依赖 v7 的正式运行，什么时候跑都可以，但不要和第二、三节的任务同时跑（都要用两张卡）。

```bash
cd 工作目录/full-model/po-jepa-full
python tools/make_addon_jobs.py --stage v7tree > jobs-addon-v7tree.txt
cd ../../po-jepa
python tools/run_jobs.py ../full-model/po-jepa-full/jobs-addon-v7tree.txt --gpus 0,1
```

（`工作目录` 换成你的实际路径。）这里用的是 v7 自己的 `run_jobs.py`，日志在 `工作目录/logs-v7/jobs-addon-v7tree/`。打印“全部完成。”就结束了。

## 五、中断了怎么办

**重新运行同一条 `run_jobs.py` 命令就行**（在原来的目录里），不用删任何东西：

- 已完成的任务会跳过；
- 训练到一半的任务会自动从断点续训（新目录名后面带 `-resumeN`），后面的任务会自动改读续训的目录；
- 其他跑了一半的任务，旧的输出目录会被改名为 `原名.brokenN` 保留，然后重跑。

关机、断电、按了 Ctrl-C、显卡出错，都是这样处理。如果同一条任务反复失败，把结果打包发给 Jerry（第六节）。

只想看看接下来要跑什么、不真正执行，在命令后面加 `--dry-run`。

补跑进行中（从试跑开始到全部传回为止）请**不要**：

- 在 `full-model` 或 `po-jepa` 里 `git pull`、`git checkout` 别的分支，或者改动里面的任何文件。代码一变，正在跑和续训的任务都会报 `delivery source changed`。需要更新代码时 Jerry 会另外说明怎么做。
- 在 `full-model/po-jepa-full` 里运行 `python run.py calibrate`（这是 v7 的标定命令）。补跑必须用从 v7 导入的标定，重新标定会让后面的任务全部报错。

## 六、传回结果

在工作目录里执行，模型权重（`.pt`）不用传：

```bash
zip -r results-addon.zip results-addon logs-addon logs-v7/jobs-addon-v7tree full-model/po-jepa-full/configs/calibration full-model/po-jepa-full/jobs-addon-*.txt -x '*.pt'
nvidia-smi > nvidia-smi.txt && zip results-addon.zip nvidia-smi.txt
```

还没跑 D3 时 `zip` 会提示 `name not matched: logs-v7/jobs-addon-v7tree`，不要紧。把 `results-addon.zip` 发给 Jerry。**`features-v7/`、v6 的特征目录（`$V6`）、`results-v7/`、`results-addon/` 和里面的模型权重都请先保留**，之后补实验还要用。

## 七、常见报错

报错信息在 `../../logs-addon/<任务文件名>/` 里对应任务的 `.log` 文件末尾（D3 的在 `工作目录/logs-v7/jobs-addon-v7tree/`）。run.py 的任务还会在输出目录里留下 `run/FAILED.json`。

| 报错关键词 | 原因和处理 |
|---|---|
| `请在 full-model/po-jepa-full 目录里运行` | 先 `cd 工作目录/full-model/po-jepa-full` 再运行（D3 例外，见第四节） |
| `试跑必须给 --v6-features` 或 `要写绝对路径` | 生成试跑任务文件时少了 `--v6-features` 或写成了相对路径，照第二节的命令重新生成 |
| `preflight 没通过` | v7 有任务没跑完，或者 v7 的特征被动过，或者（试跑）`--v6-features` 给的不是 v7 试跑用的那个目录（比如给了 git 克隆里只有说明文件的 `features/`，报 `缺 COMPLETE.json、manifest.json 或 raw_z.npy`）。日志里列出了每一项。报的是 `--v6-features` 给的那个目录、而它确实给错了：照第二节改正 `V6`、重新生成任务文件、重新运行；其他情况打包发给 Jerry，先不要往下跑 |
| `git HEAD 是 …，应为 0ac45fe…` 或 `读不到 … 的 git HEAD` | `po-jepa/` 不在 v7 正式运行的提交 0ac45fe 上（旧提交 653e2d0、911bc09 是模态写法，补跑不接受），或者不在原来的位置。报错里说的 `git pull` 先不要自己做，告诉 Jerry |
| `缺少 v7 标定` | v7 的标定没有完成，或者 v7 的试跑、正式运行有一个没跑。告诉 Jerry |
| `已存在且和 … 不同；不覆盖` | `full-model/po-jepa-full/configs/calibration/` 里有一份和 v7 不同的标定。不要删，告诉 Jerry |
| `导入记录不符` 或 `缺少 …IMPORTED.json` | 有人在 `full-model/po-jepa-full` 里运行过 `run.py calibrate` 或改过标定文件。不要删，告诉 Jerry |
| `补跑标定文件已存在` | 补跑标定已经写过一次，不会覆盖。告诉 Jerry |
| `补跑标定文件不存在` | C 段（`calibrate-addon`）还没有成功。先看 C 段的日志 |
| `λ 的分母为 0` 或 `calibrated weight must be finite and positive` | 补跑标定没算出可用的权重。这不能手填，告诉 Jerry |
| `一致性太弱` | 某个新条件被提前检查停掉了。这是一个实验结果，不是程序出错；告诉 Jerry，由他决定怎么办 |
| `dependency versions differ` | Python 包版本不对；环境应该和 v7 完全相同，先确认 `conda activate pojepa` |
| `CUDA out of memory` | 有别的程序占着显存，关掉后重新运行 |
| `delivery source changed` | 代码文件被改动过。在 `full-model/po-jepa-full` 里执行 `git checkout .` 恢复后重新运行 |
| `另一个 run_jobs.py 正在用 …` | 同一个任务文件已经有一个进程在跑，不要同时开两个 |

其他报错把结果打包发给 Jerry。

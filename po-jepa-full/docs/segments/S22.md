## 1. 目标与范围

V-JEPA 2 的 patch 是两帧一组的三维 tubelet（2×16×16）。v3–v7 每个时刻把同一帧复制两份（`vjepa.FrozenFrameEncoder`），特征里没有运动信息，二阶场景只看一帧看不到速度。规划推荐让 tubelet 吃真实的第 t−1、t 帧（PO-JEPA、损失、缓存格式都不变）。本段写验证工具：在单摆上比较“复制一帧”和“真实两帧”编码后，角速度能不能从冻结特征里线性读出。

- 交付：`src/po_jepa/tubelet_probe.py`（探针单摆、两种编码、线性探针、判据，纯函数）、`tools/tubelet_probe.py`（encode / fit / jobs）、`tests/test_s22_tubelet_probe.py`。
- 已有 .py 一个字节都没动，没有已有模块导入新文件；单摆不登记成数据集场景。DATASET.md 加了一句指向本段。
- 不做：真编码器运行（交给算力方，见 §4）；二阶场景本身（第 4 阶段）；改 `encode_v7.py` 的编码方式（探针通过后第 4 阶段做）。

## 2. 定义（公式即实现，见 `tubelet_probe.py` 模块说明）

**探针单摆**：θ̈ = −(g/L)·sin θ − γ·θ̇ + K·u，g/L = 9.81 s⁻²（小角周期 2.006 s，每周期约 8 帧），γ = 0.2 s⁻¹，K = 4 rad/s² 每单位动作，u ∈ [−0.5, 0.5]。
- 帧 f = 0…33 对应 tick t = f − 1 = −1…32（多画 t = −1 一帧，t = 0 也有前一帧）；控制周期 0.25 s，每 tick RK4 50 步。
- 动作：v6 的分段规则（段长 1/4/8、20% 零动作，随机流 1）；初值 θ ∈ U(−π, π)、θ̇ ∈ U(−3, 3)（流 0）。随机流熵 [1703, 2200, 轨迹, 流]，不与数据集场景重叠。
- 前 200 条：42 条越过顶点附近（|θ| > 0.9π），12 条净转一整圈以上；|θ̇| 最大约 7.2 rad/s，每帧转角 < 0.6π（低于奈奎斯特界，两帧之间方向没有歧义）。
- 画面：v6 深色网格背景，支点在中心，灰色抗锯齿摆杆 80 像素，橙色高斯摆锤 σ = 6 像素。画面只由 θ 决定。

**三种特征**（每个 tick t = 0…32 一个样本，每条轨迹 33 个）：
- `dup`：第 t 帧复制两份 = v7 的编码。`FrozenClipEncoder.encode_clip(b, b)` 与 `FrozenFrameEncoder.encode_target(b)` 逐元素相同（测试）。
- `pair`：第 t−1、t 帧按时间顺序组成 tubelet（推荐方案）。
- `dup_concat`：第 t−1 帧和第 t 帧的 dup 特征拼接（备选方案“模型同时吃两帧特征”能拿到的信息）；不另外编码，核 = K_dup[前,前] + K_dup[后,后]。
- 两帧的预处理都用同一条轨迹重置后的同一个 generator（v7 规则），所以裁剪相同。

**三种读出**：mean（token 平均 1408 维）、pool4（4×4 平均池化 22528 维）、full（16×16×1408 = 360448 维）。

**线性探针**：对偶岭回归。核先减去全体均值（只为数值条件），再按每折训练集均值精确中心化（k̃ = k − m(a) − m(b) + c，任何常数平移不改变结果；测试核对显式中心化和原始形式岭回归）。目标：sin θ_t、cos θ_t、θ̇_t、θ̄̇_t = wrap(θ_t − θ_{t−1})/0.25。按轨迹 5 折（轨迹编号 mod 5）：第 k 折测试、第 k+1 折选 λ、其余训练；λ = trace(K̃)/n·10^e，e ∈ {−7, −6.5, …, 2}，每个目标各选；选定后在训练 + 选 λ 两折重拟合，报测试折 R²，5 折平均（也存最小值、每折值、λ 是否在网格边上）。

**判据**（可改，只改模块里的三个常数）：pair 在某个读出上 θ̇ 的 R² ≥ 0.9，且比同一读出的 dup 高 ≥ 0.1 → 采用两帧输入；同时该读出上 dup 的 sin θ、cos θ R² 都要 ≥ 0.9，否则探针本身没读出位置，结论无效。0.9 来自规划 §1.4；0.1 和位置门槛是本段定的。三种读出里取 pair θ̇ 最高的那个（5 折平均，有轻微的选择偏差，阈值是粗粒度的）。

## 3. 工具

```
python tools/tubelet_probe.py encode --trajectories 200 --output ../features-v8/tubelet-probe-200 \
    --upstream-root ../vjepa2 --checkpoint ../checkpoints/vjepa2-vitg-fpc64-256.pth --device cuda:0 --shard 0/2
python tools/tubelet_probe.py fit --trajectories 200 --output ../features-v8/tubelet-probe-200 --device cuda:0
python tools/tubelet_probe.py jobs --shards 2 > jobs-v8-tubelet.txt     # 排队用的任务表
```

- encode：编码器构造、权重 SHA 和加载规则与 `encode_v7.py` 相同。每条轨迹存 `dup.npy` [34,256,1408]、`pair.npy` [33,256,1408]（float16）、`states.npy` [34,2]、`manifest.json`（帧 SHA、特征 SHA、tubelet 帧号、物理常数、随机流、源码 SHA、证据角色）、`COMPLETE.json`。断点续跑同 `encode_v7`。
- fit：核对每条的 COMPLETE、清单 SHA、特征 SHA，读入后算 9 个核、15 组 5 折岭回归，写 `report.json`，屏幕打印 R² 表和判据。假编码器的产物在报告里标 `synthetic_development_only`。
- 规模：200 条 × 67 个 tubelet = 13400 次编码；特征约 9.7 GB；fit 峰值内存约 10 GB，full 读出的核在 GPU 上按 32768 维分块（fp32 highest 精度相乘、float64 累加）。

## 4. 算力方怎么跑、结果怎么用

1 张卡，规划估约 1 GPU 小时以内（编码速度没在真编码器上实测）。跑完把 `report.json` 和屏幕输出发回来。
- 采用（`adopt_two_frame: true`）：第 4 阶段的二阶场景用 pair 编码（改 `encode_v7` 的编码方式时，一阶场景继续 dup，与 v7 逐位一致）。
- 不采用但 `dup_concat` 的 θ̇ R² 高：考虑备选方案（模型同时吃两帧特征），约 3–4 天，要改模型和理论部分，先问 Jerry。
- 位置都读不出：探针本身有问题，先查。

## 5. 验证

环境：Python 3.12.3、numpy 2.4.3、torch 2.11.0+cpu、PyYAML 6.0.3、scipy 1.16.3、pytest 8.4.2。

### 5.1 单元测试（`tests/test_s22_tubelet_probe.py`，17 个，约 30 秒）

- 物理：无阻尼时能量相对漂移 < 1e−8；小角解析解 θ0·cos(ω0 t)；线性化 + 阻尼 + 常力矩的解析阶跃响应；无动作时能量单调减；子步数 50 对 200 差 < 1e−7；随机流、动作分段与独立重算一致；前 200 条每帧转角 < 0.8π，且有越过顶点的、也有一直在下半圈的。
- 画面：只由 θ 决定（θ 相同、θ̇ 不同的两帧逐位相同）；橙色像素质心与 `bob_rc` 差 < 1 像素；摆杆在中点可见。
- 目标对齐（tick 0…32；wrap 在跨 ±π 时生效）；tubelet 帧号和样本行号。
- 编码器：小型 Conv3d tubelet 编码器上，`encode_clip(b, b)` 等于 v7 的 `FrozenFrameEncoder`；pair 的第 0 个时间片是前一帧；eval、冻结、dtype、batch 检查会报错。假编码器下 `encode_trajectory` 每一行等于对应帧号的单独编码。
- 探针：读出的池化；三种读出的核等于显式中心化的 XXᵀ；dup_concat 的核等于显式拼接；对偶岭回归等于原始形式；有信号 R² > 0.99、纯噪声 R² < 0.05；按轨迹分折（独热轨迹特征在按轨迹分折时 R² ≤ 0，按样本分折时 > 0.9）；判据的四种情况和“取最好的读出”。
- 工具端到端（假编码器，10 条、两片）：清单内容、状态与重算一致、报告结构；pool4 读出上 dup 的 θ̇ R² < 0.1，pair 高出 0.2 以上，位置 R² > 0.9；已完成的跳过；缺一条时 fit 拒绝；特征被改时 fit 拒绝；jobs 的分片和段顺序；没给编码器路径时拒绝。

## 1. 目标与范围

**Jerry 2026-11-25 定（新口径）**：两帧编码（`tubelet=pair`）后目标特征带了速度，二阶场景（pendulum、cart_pole、spring_chain、bouncing_balls、wave）的规划成功判据并入速度：到了位置但速度不对算失败；读出任务同时加上速度。这是新的评测口径，**二阶场景的规划成功率、oracle 结果和读出结果与 S25b5 之前的不可比**。速度容差 Jerry 在决策卡选“按位置容差换算”（§2）。

交接里一直写的“读出任务加速度”是“加上速度”，不是加速度（acceleration）：两帧编码只看得到速度，加速度至少要三帧（`runtime/state_readout.py` 原注释“S25b 接 pair 编码后可以加速度”）。

不做：一阶场景和 push（状态里没有速度，判据、代价、报告逐位不变）；目标的抽法和门槛（`goal_far_enough` 仍只看位置，回合是同一批）；模型规划的代价（仍是到目标特征的 JEPA 距离）；任务表命令行（不变）。训练的源码身份（`data.consumer_sources`、`comparison.consumer_sources`）列的文件一个都没改。

## 2. 定义（公式即实现）

记 τ = `plan_v7.VELOCITY_SECONDS` = 1 tick = 0.25 s（两帧编码的间隔，Jerry 2026-11-22 定的前一帧口径）。

- **速度**（`configuration.velocity`）：构形的时间导数，由隐藏状态解析算出（不做差分），单位是构形单位/秒：
  - pendulum (θ, θ̇)：d/dt (sin θ, −cos θ) = θ̇·(cos θ, sin θ)
  - cart_pole (x, ẋ, θ, θ̇)：d/dt (x, x + l·sin θ, l·cos θ) = (ẋ, ẋ + l·θ̇·cos θ, −l·θ̇·sin θ)
  - spring_chain、bouncing_balls：速度 [2n]（隐藏状态后一半）
  - wave：u_t 的 16×16 平均池化场（池化线性，等于池化 u 的时间导数）
  - `controlled_velocity`：规划摘要 `controlled` 的时间导数（spring_chain、bouncing_balls 取第 0 个）。
- **规划成功判据**（`plan_v7.success`）：e_q = ‖摘要(终点) − 摘要(目标)‖，e_v = ‖摘要速度(终点) − 摘要速度(目标)‖，e_q0 = “不动”的 e_q：
  成功 ⇔ max(e_q, τ·e_v) ≤ `--success`（默认 0.5）× max(e_q0, 1e−9)。速度容差跟“不动”的**位置**误差走，含义是“两帧间隔内速度误差造成的位移不超过位置的容差”。没有速度的场景就是旧判据 e_q ≤ 0.5·e_q0。
- **oracle 代价**（`plan_v7.oracle_target`）：二阶场景是 [摘要, τ·摘要速度]，到目标的 L2 = √(e_q² + τ²·e_v²)，使 oracle 仍是新判据下的上界。
- **报告**：二阶场景每个回合多 `velocity` = {model, oracle, random, zero 的 e_v}；`model`/`oracle`/`random` 多 `position_only_success_rate`（旧判据）、`mean_velocity_error`、`mean_velocity_error_px_per_s`（wave 为 None）；`zero` 多 `mean_velocity_error`；顶层 `success_rule` 改写、多 `success_metric`（版本 S25b5、τ、说明不可比）。
- **判据属于任务本身**：单帧复制（dup，特征看不到速度）的对照也用同一条，dup 与 pair 才可比。
- **速度读出目标**（`state_readout.velocity_target`）：`configuration.velocity` × 每单位像素（像素/秒）；wave 不乘（场的 L2/秒）。与位置目标同一比例，所以它是位置目标沿真实轨迹的时间导数。
- **速度探针**：同一份特征、同一个 `state_readout.fit`，单独选 λ，所以位置探针和只拟合位置时逐位相同；存在探针目录的 `velocity/` 子目录，`probe.json` 的 `quantity = "velocity"`（位置探针 `quantity = "position"`，S25b5 之前没有这个键，按 position 读）。
- **读出指标**：滚动的 vel_readout:T、vel_floor:T、vel_nmse:T、vel_floor_nmse:T、vel_vpt@ε、vel_floor_vpt@ε，反事实的 vel_cf_true … vel_actual_floor，定义与位置逐条相同，R、y、V 换成速度探针的；反事实汇总在 `overall.velocity`、`by_duration.<t>.velocity`。
- **拒绝旧文件**：二阶场景的 rollout、counterfactual 要求真值文件有 `velocity: true`、探针目录有 `velocity/`，且速度探针和位置探针的缓存身份、轨迹、tubelet、读出 kind 相同；S25b5 之前做的探针和真值要用当前代码重做 fit、truth（二阶场景的读出还没在 GPU 上跑过）。

## 5. 验收

### 5.1 测试（`tests/test_s25b5_velocity_success.py`）

1. 二阶场景集合、τ = `systems.PERIOD` = 0.25。
2. 四个质点类场景的速度 = 构形沿速度方向扰动的中心差分；摆锤、小车倒立摆按手写公式；摆长跟参数走；受控速度取第 0 个。
3. wave 的速度 = 整场 u_t 直接池化。
4. 速度读出目标的比例（80、36、48、场不乘），一阶场景拒绝。
5. 判据表：到了位置速度不对失败、速度对位置不对失败、边界、容差跟不动的位置误差走、e_q0 下限。
6. 五个二阶场景 oracle 代价 = √(Δq² + τ²Δv²)；一阶场景、push 不变。
7. pendulum 规划端到端：成功率和旧判据成功率从回合行独立重算；第一个回合的“不动”和目标独立重做，速度误差按手写公式；double_well 报告没有新字段。
8. 读出公式：带速度时位置指标不变，vel_ 一半 = 只拿速度探针算；反事实同理；汇总 velocity 按手算值。
9. 探针的 quantity 核对；S25b5 之前的探针按 position 读。
10. 工具端到端（pendulum~tubelet=pair，假编码器缓存当真实读）：fit 写 velocity/、truth 的速度按手写公式；位置探针和关掉速度时拟合的逐字节相同；rollout、counterfactual 的 vel_ 指标独立重算一个点；拒绝没有速度的真值、没有 velocity/ 的探针、不是同一份缓存的速度探针。

## 1. 目标与范围

v8 规划 §1.5 的“空间采样”：渲染分辨率 192/256/320/384（对应 12/16/20/24 网格；V-JEPA 2 用 3D-RoPE，可以直接编码其他分辨率）、缩放、相机平移和缓慢漂移，对应论文的“原始分辨率 OOD”。S24c 已经能按原生分辨率和相机生成画面，但编码、缓存和评测都拒绝空间采样调节项。本段把这条链接上：按原生分辨率编码空间采样测试集（只测试段）、读特征网格可变的缓存、用基础场景上训练好的模型在主实验测试窗口上评测并和基础测试集同一窗口配对、任务表和汇总。

12 个场景都适用（二阶场景照 S25a 的规矩要显式 `--scenes`，按 dup 编码）。

不做：用空间采样数据训练；空间采样和 `horizon` ≠ 32、时间采样组合（编码和读取都报错）；空间采样的动作探针和规划（仍报错）；pair 编码（S25b）；新任务（S25f）。

## 3. 约定（Claude 定，Jerry 可以改）

1. **测试项**（`protocols.SPACE_TESTS`）：`resolution=192`、`resolution=320`、`resolution=384`、`zoom=0.75`、`pan=1,zoom=0.75`、`drift=0.5,pan=1,zoom=0.75`。分辨率三档是规划里的三个非训练分辨率；相机三项都叠在 zoom=0.75 上，所以 pan、drift 的效果相对 zoom=0.75 单独一项来读（zoom=0.5 这个极端没进默认表，要加只改这一行）。每类 200 条测试段、33 帧。
2. **原生分辨率编码**：不把 R×R 的画面缩放回 256。预处理仍是官方 `random_resized_crop`、同一组 scale/ratio/均值方差、同一个“每帧前重置同一条轨迹的 generator”规则，只把输出边长换成 R。scale = 1.777 > 1 时十次尝试都不成立（目标面积大于整图），回退到整张图，再 R→R 双线性插值（align_corners=False，源坐标落在像素中心上，是恒等），所以对 R×R 的画面它就是逐像素归一化；R = 256 时与 v7 逐位相同。编码器是同一个冻结 ViT-g，上游 VisionTransformer 默认 `handle_nonsquare_inputs=True`，按输入算 H_patches = W_patches = R/16 交给 RoPEAttention，位置是整数 0…R/16 − 1（不缩放）：192 的位置是 256 的子集，320、384 外推到 0…15 以外（上游提交 204698b 的 `src/models/vision_transformer.py` forward、`src/models/utils/modules.py` RoPEAttention.separate_positions，静态读过，没在本机跑上游代码）。
3. **预处理记录和摘要**：manifest 的 `generation.preprocess` = v7 的记录 + `crop_size = R` + `native_resolution = R`，`preprocess_sha256` 按它算（规则字符串同 v7）。因为多了 `native_resolution`，zoom/pan/drift（R = 256）的缓存摘要也和 v7 不同，`cache.read_window` 一律不收空间采样缓存（测试核）。
4. **模型怎么吃 G×G**（模型都不改）：PO-JEPA 在 G×G 的特征上建图、求最低 K 个模态；Transformer 的位置嵌入是归一化坐标 ((x+0.5)/G, (y+0.5)/G) 的线性函数；V-JEPA 2-AC 用官方 RoPE，位置按 16/G 缩放到 16 格上（ac_baseline 文件头，和 v7 的 8×8、12×12 一样）。时长都是整数 tick，三者都直接调 forward；identity 是 d(z_s, z_{s+T})。zoom/pan/drift 的网格仍是 16×16，只有画面不同。
5. **窗口和指标**（`space_eval.py` 文件头）：窗口就是主实验的测试窗口（`datasets.test_start_ticks` 的起点 s，时长 1、2、3、4、8、12 tick）。`direct:T` = 空间采样测试集上 d(Φ_T(z_s), z_{s+T})（d4.direct_prediction 的写法，同 v7 point_metrics 的 future_jepa_distance）；`base_direct:T` = 同一个模型、同一窗口在基础测试集（主实验缓存）上的同一个量；`gap:T` = 两者之差（逐窗口配对）。不做 TCD、SCD、Δ_act。JEPA 距离是 token 平均，不同网格的数值可以并排看，但不同分辨率下 V-JEPA 2 的特征本身不同，gap 量的是“冻结编码器 + 模型”整条链的退化。
6. **只编码测试段**；模型在 256、相机不动的基础场景上训练，空间采样数据只评测。384 时 float16 每条约 53 MB（每类约 11 GB）。
7. **任务表**：S3 跑 3 个种子（同 S25c、S25d）；默认 7 个场景时 S3 是 7×6×3×6 = 756 条，每条要评基础测试集和空间采样测试集各 200 条 × 2 个起点 × 6 个时长。

## 5. 遗留

- 空间采样 + 长时程、空间采样 + 时间采样、空间采样的动作探针和规划：没接。
- 二阶场景是 dup 编码（看不到速度）；S25b 接 pair 编码后要重编。
- 真实 ViT-g 在 320、384 输入下的显存和速度没量过（token 数 400、576，比 256 多 1.6、2.25 倍；编码按 33 帧一批）。
- 上游编码器对非 256 输入的行为是静态读代码确认的（handle_nonsquare_inputs 默认 True）；第一次在 GPU 上编码时，建议先用 `--trajectories 2000 --shard 0/200` 编几条看形状。

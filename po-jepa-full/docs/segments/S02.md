## 3. 接口

- `run_index(config, data_root, *, get, sleep, threads=32, clock) -> manifest`：`index/MANIFEST.json` 已存在就不联网、直接返回它（先核它是本代码写的：schema 是 `droid_index_v1`、`files` 正好是本代码写的那几个文件，否则报错，要人把旧索引挪开）。
- `verify_sample(config, data_root, count)`：先核三个文件和清单里的 SHA、行数一致，再按 `h("verify", name)` 升序取 `count` 份重新下载（大小和 MD5 照列表核），和 `metadata.jsonl` 那一行逐字段、连键顺序一起比较。
- `python -m po_jepa.droid.index --config configs/droid/<name>.yaml --data-root <数据根> [--verify-sample N]`。
- `salted_hash(salt, kind, key)` = `sha256(f"{salt}|{kind}|{key}")` 的十六进制串。

文件格式：

| 文件 | 每行 |
|---|---|
| `listing.jsonl` | 列表接口返回的一项（`name`、`size`（字符串，GCS 原样）、`md5Hash`、`crc32c`、`updated`），键排序，按 `name` 排序 |
| `metadata.jsonl` | 官方元数据原键顺序，末尾加 `_name`、`_md5`（列表里的 base64 MD5）、`_size`（int）；按列表顺序 |
| `episodes.jsonl` | 02 §3 的 12 个字段 + 5 个只作记录的字段 + `selected` + `reasons`，键排序；按 (`uuid`, `folder`) 排序 |

每行都是紧凑 JSON（`separators=(",", ":")`、`ensure_ascii=False`、不收 NaN），文件先写 `<名>.partial` 再换名；`MANIFEST.json` 用 `cache._write_json`。

`MANIFEST.json`：`schema`、`data_version`、`config_keys`（影响索引的配置键：`list_api`、`prefix`、`camera`、`expected_metadata_files`、`min_steps`、`ood_labs`）、`listed_at`（列表完成时刻，UTC）、`metadata_reused`、`code_commit`（git HEAD，不在 git 检出里为 null）、`code_manifest_sha256`（`po-jepa-full/MANIFEST.json` 的 SHA）、`files`（每个文件的 `sha256` 和 `lines`）、`counts`（总条数、入选数、按组和实验室的入选数、四种原因各自的条数）。

## 4. 实现上自己定的（规格没写死、可逆）

1. **清单先记三个文件**：02 §7 说清单记四个文件，第四个 `splits.json` 是 S03 的产物。本段的 `INDEX_FILES` 只有三个；S03 把 `splits.json` 加进 `INDEX_FILES`，并在写清单之前写划分。老代码写的清单（三个文件）会被新代码认出来并报错，不会被当成已完成。
2. **重试**：任何失败（连接、非 200、JSON 不合法、大小或 MD5 不对）都按同一规则重试：共 1 + 5 次，间隔 1、2、4、8、16 秒，仍失败就报错并写明页号或对象名。404 也重试（规格没区分；最多多等 31 秒）。
3. **对象地址**用 `{data.object_base}/` 后接对象名去掉 `data.prefix` 的部分（URL 编码，`:`、`+` 编码成 `%3A`、`%2B`），等于 02 §2 写的 `https://storage.googleapis.com/gresearch/<name>`，测试时可以换成本地地址（和 03 §5 一致）。
4. **列表检查**：除了条数，还查每项的 `name` 在前缀下、`size` 是十进制字符串、`md5Hash` 是 16 字节的 base64；对象名不能重复；`nextPageToken` 不能重复（防死循环）。
5. **元数据的 JSON**：严格解析（不收 NaN/Infinity、对象里不能有重复键）；官方字段里已有 `_` 开头的键就报错（防止和三个附加字段冲突）。
6. **§3 的几处细化**：`h5` 必须以 `folder + "/"` 开头（防止 `…_2023x/` 这种同前缀的兄弟文件夹）；`left_mp4` 必须是直接在 `<folder>/recordings/MP4/` 下的 `.mp4` 文件（不在子目录里）；相机序列号按字符串比较（元数据里是字符串，是 int 也认），两个外部相机都对上也报错；对象名至少要有 `<lab>/<outcome>/<文件名>` 三段且没有空段。左相机用哪个字段取自 `data.camera`。
7. **只作记录的 5 个字段**（`building` 等）缺了也报错（真实数据上全都有）。
8. **重跑**：`metadata.jsonl` 每行的 `_name` 和 `_md5` 都和新列表逐行一致才跳过下载（任何一行不一致或文件读不了就整份重下，覆盖旧文件）；`listing.jsonl`、`episodes.jsonl` 每次重写。清单在最后写。

# S25b 第一段：二阶场景的两帧（pair）编码接进特征缓存

2026-11-22 · v8 数据集扩展第 6 阶段第二段的第一部分 · 依赖：S22（两帧 tubelet 探针，2026-11-19 结果：采用两帧输入）、S23b（二阶场景登记、`frames_with_prev`）、S25c（长时程缓存）· 基于 full-model 3d94f77 · 分支 `seg/S25b-pair-encoding`

这份文件是本段的说明和验收单，审核 agent 按 §7 逐条核对。

## 1. 目标与范围

五个二阶场景（pendulum、bouncing_balls、wave、cart_pole、spring_chain）一帧画面只给位置。v7 的编码把同一帧复制两份送进 V-JEPA 2 的 tubelet（两帧一组的三维 patch），特征里没有速度。S22 探针在真编码器上的结果（G2，2026-11-19）：单摆角速度 θ̇ 的线性读出 R²，两帧 0.962、单帧复制 0.003（读出 pool4），判据通过，采用两帧输入。

本段把两帧编码接进 `tools/encode_v7.py` 写的特征缓存（33 帧主缓存和 64/128 长时程缓存）。PO-JEPA、损失、缓存格式、训练和评测入口都不变：每个时刻仍是一个 16×16×1408 的特征场，只是这个场带了速度。

不做（S25b 第二段）：`probe_actions.py` 的反事实终点、`plan_v7.py` 的目标和重规划画面的在线两帧编码；`tubelet=pair` 加时间采样、空间采样；二阶场景并进 v8 任务表默认、协议表里二阶场景的测试格带上 `tubelet=pair`；读出任务加速度。

## 2. 设计：为什么是调节项

两帧编码写成调节项 `tubelet=pair`（默认 `dup`），只用于二阶场景：`pendulum~tubelet=pair:2000`。

- `src/po_jepa/runtime/cache.py` 被 S18a 的测试钉了 SHA，又在训练的源码身份（`data.consumer_sources`）里，不能改。它读缓存时本来就核 manifest 的调节项字符串等于当前数据集的；整套缓存的摘要（`data._v7_cache_metadata`）也核。所以写成调节项后，不改这两个文件就能保证 pair 和 dup 的缓存互相读不到（测试核），特征目录、结果目录、报告里的数据集名也自动带上 `tubelet=pair`。
- 反过来把 pair 做成二阶场景的默认，旧的 dup 缓存调节项也是空字符串，`cache.py` 分不出来。
- 不带 `tubelet=pair` 的二阶场景照旧是单帧复制：编码操作和数据口径不变，已有测试照旧通过，可以当“看不到速度”的对照。新编出来的 manifest 字节会变，因为它记的生成源码 SHA（`variants.py`、`encode_v7.py`）随本段更新。
- 一阶场景给 `tubelet=pair` 直接报错：一帧就能看全状态，继续用 v7 的单帧复制，与已有缓存逐位一致。
- `tubelet` 只改“画面怎样送进冻结编码器”，不改物理、动作、画面和任何随机流：同一编号的轨迹在 pair、dup 数据集下的状态、34 帧画面、下达动作逐位相同（测试核五个场景）。
- `run.py transfer --test-variant` 把测试调节项并到训练数据集的调节项上（`v7jobs.transfer_job`，同名以测试为准），长时程评测用 `protocols.merged`，所以两帧特征上训练的任务，测试集自动也是两帧的。`--test-variant` 里写 `tubelet=…` 会跨口径（两帧模型读单帧缓存或反过来），由 `workflow.refuse_tubelet_test_variant` 在调 `transfer_job` 之前拒绝（Codex 审核 F1；`v7jobs.py` 在训练的源码身份里，不改它）。`plan_v7.py --test-variant` 是整个替换，本段让它见到任何一边带 `tubelet=pair` 都拒绝。
- 隔离的前提：正式入口一个进程只有一个数据集。`cache._VERIFIED_CACHE` 的键里没有数据集（§5 末条），同一进程里换数据集重读同一目录不在保证之内。

## 3. 定义（公式即实现）

记第 t 个控制 tick 的画面为 I_t（t = −1, 0, …, H；H = 32，长时程 64、128；相邻两帧相隔 1 tick = 0.25 s = V-JEPA 2 预训练的 4 fps）。t = −1 是抽初值的时刻，零动作预跑一个 tick 到 t = 0（S23a 的约定，`systems.SecondOrderSystem.frames_with_prev` 给出 H+2 帧，下标 f = tick f−1）。

- 预处理：P(I) = v7 的固定 DROID 变换，每帧单独做，之前把这条轨迹的 generator 重置到同一状态（种子 = 随机流 2）。所以一条轨迹所有帧的裁剪相同，两帧之间不会因为裁剪不同出现假的运动。
- dup（v7）：Z_t = E([P(I_t), P(I_t)])。
- pair（本段）：Z_t = E([P(I_{t−1}), P(I_t)])，t = 0…H，时间顺序是（前，后）。E 是同一个冻结的 V-JEPA 2 ViT-g 编码器，输入 [B,3,2,256,256]，输出 [B,256,1408]。
- 编码器类是 S22 探针用的 `tubelet_probe.FrozenClipEncoder`（继承 `vjepa.FrozenFrameEncoder`，冻结、eval、设备、dtype 的设置和检查相同；两帧相同时与 dup 逐元素相同，S22 的测试核）。G2 的证据就是用这个类、这条预处理规则在真编码器上得到的。
- 分批：第 k 批是第 33k…33k+32 个 tubelet（`--batch 33`）。33 帧主缓存是一批；长时程的前 33 个 tubelet 与主缓存那一批输入逐位相同（S25c 的约定照搬）。

## 5. 约定和遗留

- **时间采样下前一帧怎么取（Jerry 2026-11-22 定）**：固定取 0.25 s（1 tick）前的画面，不取视频流里的上一帧。这样编码器输入的两帧间隔始终和训练一致，特征只由物理状态决定，帧率测试只考模型的跨时间离散一致性，fps = 2 也能测。`timing.frames(prev=True)` 现在给的是“往前一个帧间隔”，不是这个口径；第二段要另画这些帧。本段 `variants.validate` 拒绝 `tubelet=pair` 加时间采样调节项。
- 空间采样要原生分辨率的两帧编码器（`native_encoder` 的 pair 版），第二段接；本段同样拒绝。
- 探针和规划：反事实终点的前一帧是反事实轨迹上一个 tick 的状态（时长 1 时就是真实起点）；规划目标的前一帧是目标动作序列上一个 tick 的状态，重规划画面的前一帧是上一步执行后的状态。第二段接，接的时候 `plan_v7 --test-variant` 要求训练和测试数据集的 tubelet 相同。
- 任务表：`make_v8_jobs` 默认仍只排一阶场景；第二段把二阶场景按 `<场景>~tubelet=pair` 并进默认。
- 读出任务（S25f）对二阶场景只读位置；两帧编码下可以加速度，属于新的评测口径，第二段提出来。
- `cache._VERIFIED_CACHE` 的键里没有数据集（已有行为，`long_cache` 的文件头写过）：同一进程里换数据集重读同一目录会复用核过的结果。正式入口一个进程只有一个数据集，不受影响；测试里换数据集前要清。

## 6. 验证

环境：Python 3.12、numpy 2.4.3、torch 2.11.0+cpu、PyYAML 6.0.3、scipy 1.16.3、pytest 8.4.2。CPU 验证，没跑真编码器（真编码器上的证据是 S22 的 G2）。

### 6.1 单元测试（`tests/test_s25b_pair_encoding.py`，42 个，约 75 秒）

期望值都从画面独立重算。
- 调节项：解析、规范字符串、数据集名；一阶场景（含 landscape）拒绝；非法取值拒绝；覆盖表是五个二阶场景；`tubelet=pair` 加 fps、jitter、exposure、switch_offset、resolution、zoom 各自拒绝（不带 pair 时这些调节项可用）。
- 五个二阶场景：pair 和 dup 数据集下同一条轨迹的状态、34 帧画面、33 帧画面、下达动作逐位相同。
- 缓存产物（假 tubelet 编码器，pendulum:40 测试段）：每条的特征等于独立重算的（前，后）tubelet 编码；不等于（后，前）和单帧复制；tick t 的特征等于只拿第 t−1、t 两帧单独编码；states 是 tick 0…32；manifest 的 tubelet 记录、t = −1 帧的 SHA、逐帧 SHA、与 dup manifest 相同的字段、生成源码；report 的 tubelet。
- 不带 `tubelet=pair` 的二阶场景：特征等于独立重算的单帧假编码器输出（没变）。
- 长时程：66 帧 → 65 个特征，等于独立重算；前 33 个与主缓存一致。
- 真实编码路径（`fake=False`，记录输入的替身）：每帧单独预处理且 generator 重置到流 2 的种子（种子独立写出，不调 `preprocess_seed`）；第 k 个 tubelet 是（第 k 帧，第 k+1 帧）；输出行序；33 分批，长时程第一批与主缓存逐位相同；batch = 5 时不落不重；不调单帧的 `encode_target`。
- `FrozenClipEncoder`：小型 Conv3d tubelet 编码器上，输出等于“前一帧过时间片 0 的权重 + 后一帧过时间片 1 的权重”的手算值；两帧相同时等于 `FrozenFrameEncoder`。
- 读取：pair 数据集读 pair 缓存成功、取到的起点和目标是第 5、9 行；pair 数据集读 dup 缓存、dup 数据集读 pair 缓存都被 `cache.read_window` 拒绝；`data._v7_cache_metadata` 同样；`long_cache` 核调节项和 tubelet 记录（缺记录、mode 不对、dup 数据集多出记录，其余字段自洽）。
- finalize：manifest 自洽但缺 tubelet 记录、mode 不对、dup 目录多出记录、整个目录是另一种 tubelet，都拒绝。
- tubelet 记录逐项核（Codex 审核 F3，13 个反例各改一项）：只有 mode、时间顺序、偏移的符号和类型、预处理规则、first_prev 的 tick、时刻、SHA 格式、缺字段、多字段；finalize 和 `long_cache` 都走这个核对。
- transfer（F1）：`--test-variant` 写 `tubelet=dup`、`tubelet=pair`（单独或和别的一起）拒绝；正式入口和 CPU 冒烟在 `transfer_job` 之前调这道检查；只改 `gain` 时测试集是 `gain=2,tubelet=pair`。
- `ac_context_check floor`（F2）拒绝 pair 数据集。
- 一阶场景 `encode --variant tubelet=pair` 在建目录前报错；`probe_actions` 拒绝 pair 数据集；`plan_v7` 的拒绝在载入模型之前。

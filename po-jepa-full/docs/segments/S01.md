## 3. 规格补漏（写代码时发现，已改进规格）

1. `droid_control_spec` 的签名多一个 `config: DroidConfig`：01 §5.3 说界“取自配置”、周期是名义值，原签名没有配置可取。
2. `action_scale.json` 的格式原来没定（S05 写、S01 读）：顶层 `realized`、`commanded` 两个键，各自正好是 `{position, rotation, gripper}` 三个正的有限 float；其他顶层键只作记录。definition_source 里的 SHA = `sha256(cache._json_bytes(scale))`，等于 `_write_json` 写出的文件 SHA。写进了 01 §5.3 和 04 §6。
3. scipy 原来不是依赖。锁 1.16.3；1.15.3、1.16.3、1.17.1、1.18.1 在 5 条金标准回合上都和参照逐位相同（实测）。
4. 上游 `poses_to_diffs` 是 `DROIDVideoDataset` 的方法（带 `self`）；这里是模块函数，函数体按 AST 相同。

## 4. 实现上自己定的（规格没写死、可逆）

- `load_config(path)` 读 `path` 同目录的 `base.yaml`；`path` 本身就是 base.yaml 时 overlay 为空（于是 `name` 仍是 base，报错）。
- overlay 的键检查：先查 base 里有没有（“不在 base.yaml 里”），再查是否在 01 §2 名单或 `resources.` 下（“不能覆盖”）。`resources.*` 下的字典继续逐键查存在性。
- 类型检查按 dataclass 注解：int 不收 bool 和 float；float 收 int（转成 float）但不收 bool、NaN、inf；字符串必须非空（两个 salt 的“非空”由它保证）；列表转 tuple。先校验一次再算 SHA，这样 NaN 报的是类型错误而不是 JSON 编码错误。
- 多两条 01 没写的校验：`name` 必须是普通目录名（运行根下的子目录名），`model.spectral_backend` 在 09 §6.3 的三个后端里；`schema` 必须是 `droid_config_v1`。
- 推导量用整数算：校验已要求 U 是 400 的倍数，0.05U、0.10U、0.04U 都是整数，等于 `round(·)`。
- `loss_config` 的五项（`jepa_exponent`、`layer_norm_epsilon`、`time_epsilon`、`space_epsilon`、`consistency_metric`）来自 `checks.load_protocol()["loss"]`，调用期间用 `patch.dict(os.environ)` 设 `PO_JEPA_PROTOCOL=v7`、去掉种子和步数环境变量，退出后环境原样恢复。现在 v6、v7 这五项取值相同（1、1e-5、1e-8、1e-8、input_scale）。

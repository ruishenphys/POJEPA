## 1. 目标与范围

第一段只让 `encode_v7.py` 写两帧缓存；三个自己重画画面、现场编码的工具（`tools/probe_actions.py`、`tools/plan_v7.py`、`tools/ac_context_check.py floor`）遇到 `tubelet=pair` 的数据集先拒绝。本段把它们接上，规则和缓存相同：

Z_t = E([P(I_{t−1}), P(I_t)])，时间顺序（前，后），前一帧永远是 1 tick（0.25 s）前的画面，每帧单独预处理、同一条轨迹的 generator 重置到同一状态。

不做（后续线程）：`tubelet=pair` 加时间采样、空间采样（`variants.validate` 仍拒绝）；二阶场景并进协议表和 `make_v8_jobs` 默认、GPU_TASKS 条目；读出任务加速度（新评测口径，要先问 Jerry）。

不带 `tubelet=pair` 的数据集（一阶场景、单帧复制的二阶场景）：三个工具的编码调用、报告字段不变。

## 2. 前一帧取什么（公式即实现）

记 q(t) 是某条轨迹在 tick t 的完整物理状态，R(q, t) 是按 tick t 画出来的画面（会动的干扰光点、像素噪声按 tick 取）。

| 工具 | 要编码的时刻 | 后一帧 | 前一帧 |
|---|---|---|---|
| 探针：真实轨迹 tick t = 0…32 | Z_t | `frames_with_prev` 下标 t+1 | 下标 t（t = 0 时是 t = −1 那一帧） |
| 探针：反事实终点 tick s+τ | Z_cf | R(q_cf(s+τ), s+τ) | R(q_cf(s+τ−1), s+τ−1)；q_cf 从真实起点 q(s) 出发、窗口内换成 donor 的下达动作；τ = 1 时 q_cf(s) = q(s)，就是真实起点那一帧 |
| 规划：起点 tick s | z_now | 测试轨迹 tick s 的画面 | 测试轨迹 tick s−1 的画面（`frames_with_prev` 下标 s；s = 0 时是 t = −1 那一帧）。和缓存里这条轨迹第 s 行是同一个输入 |
| 规划：目标 tick s+H | z_goal | R(q_g(s+H), s+H) | R(q_g(s+H−1), s+H−1)；q_g 从起点按目标动作序列续算；H = 1 时是起点状态 |
| 规划：重规划（执行到 tick t） | z_now | R(q_e(t), t) | R(q_e(t−1), t−1)；q_e 是实际执行轨迹。`--replan 1` 时就是上一步执行后的画面；`--replan 2` 时是这一步中间那个 tick，不是上一次观测到的画面 |
| floor：重编码 tick 0…32 | Z_t | `frames_with_prev` 下标 t+1 | 下标 t |

- 重规划的前一帧取“1 tick 前”而不是“上一次观测”，和 Jerry 2026-11-22 给时间采样定的口径是同一条：编码器输入的两帧间隔始终等于训练时的 0.25 s。
- 目标特征因此带着“按目标动作到达时”的速度。规划代价仍是到目标特征的 JEPA 距离；状态误差、成功判据仍只看位置（构形，S25a），没改。
- `plan_v7.py --test-variant` 是整个替换训练数据集的调节项：训练和测试的 `tubelet` 必须相同（`check_same_tubelet`，在建模型、读 checkpoint 之前），否则拒绝。两帧任务做分布外规划要写 `--test-variant gain=2,tubelet=pair`。
- 编码器类：`tubelet=pair` 时是 `tubelet_probe.FrozenClipEncoder`（`encode_v7` 写两帧缓存用的同一个），否则仍是 `vjepa.FrozenFrameEncoder`。三个工具都经 `encode_v7._encode_trajectory(..., pair=True)` 编码，和写缓存是同一个函数。

## 4. 约定和遗留

- 探针的 `D_cf`（字段名 `oracle_delta_act`）在 pair 下包含速度的差别：换动作以后位置几乎没变、速度变了，`D_cf` 也会大于 0。这是两帧编码本来要的效果（特征里有速度），报告的 `motion_units` 写明。
- 规划的 `goal_valid` 门槛、成功判据仍只看位置；目标特征带速度后，“到了位置但速度不对”的规划在特征代价上会被罚，在成功率上不罚。要不要把速度并进成功判据属于新评测口径，没动，和读出任务加速度一起提。
- 时间采样、空间采样、长时程的数据集，三个工具本来就拒绝（S24a–c、`_refuse_sampling`），没变。
- CPU 验证，没跑真编码器。真编码器路径用记录输入的替身核了：建的是两帧编码器类、输入是按时间顺序的两张预处理图、不调单帧的 `encode_target`。

## 5. 验证

环境：Python 3.12、numpy 2.4.3、torch 2.11.0+cpu、PyYAML 6.0.3、scipy 1.16.3、pytest 8.4.2。

### 5.1 单元测试（`tests/test_s25b2_online_pair.py`，23 个，约 55 秒）

期望值都从物理和画面独立重算（`variant_trajectory`、`draw`、`fake_tubelet_encoder`），不拿被测工具的函数当参照。

- 探针 `counterfactual_end(with_prev=True)`（五个二阶场景，带像素噪声、会动的干扰点、延迟等调节项，τ = 1、2、8）：换成自己的动作时两帧等于数据集的 tick s+τ−1、s+τ；换成 donor 的动作时两帧等于独立续算的最后两个状态按各自的 tick 画出来；τ = 1 时前一帧是真实起点帧；不带 `with_prev` 的返回没变；一阶场景给 `with_prev` 报错。
- 探针整机（假编码器，子进程）：报告每一行的 `identity`、`oracle_delta_act` 等于独立算的两帧特征距离；时间顺序反了、前一帧取成终点自己、取成真实轨迹的前一帧，值都不同。不带 `tubelet=pair` 的二阶场景仍等于单帧假编码器的值。
- 探针 `--features-root`：重新编码与 `encode_v7` 写的 pair 缓存一致；拿 dup 缓存来比就报不一致。
- 探针真实编码路径（替身）：建的是 `FrozenClipEncoder`，第一批是 34 帧的（第 k 帧，第 k+1 帧）33 个 tubelet，数值与假编码器那次相同；构造单帧编码器会直接报错。
- 规划 `rollout_path`：第 j 个状态等于只走 j 个 tick 的独立续算，带延迟也对；`rollout` 是它的最后一个。
- 规划 `check_same_tubelet`：四种一致的组合通过，四种不一致的拒绝；调用位置在载入模型之前。命令行：pair 任务能跑、`--test-variant gain=2` 拒绝、`gain=2,tubelet=pair` 能跑且测试集名字对；dup 任务加 `--test-variant tubelet=pair` 拒绝。
- 规划整机（本进程，记下每次送编码器的画面和每次续算，`--replan` 1 和 2）：第一次编码是目标的两帧（独立重抽目标动作、独立续算、独立画），第二次是起点的 `frames_with_prev[0:2]`，之后每次重规划的两帧等于执行轨迹最后两个状态的画面；`--replan 1` 时前一帧等于上一次送编码器的后一帧，`--replan 2` 时不等；报告的 `zero`、`model` 误差等于独立算的摆锤位置距离。第 21 个回合（起点 tick 5）的起点两帧是数据集的 tick 4、5。
- 规划真实编码路径（替身）：`FrozenClipEncoder`，每次 1 个 tubelet，时间顺序（前，后）。dup 数据集仍每次编 1 帧。
- floor：pair 缓存重编码后 `rerun` = 0、`vs_cache` ≈ 存储舍入、批大小 33、33、1×33（按 tubelet 计），第一批输入是 34 帧的（第 k 帧，第 k+1 帧）；改掉 t = −1 那一帧或中间一帧都报哈希不符；manifest 缺 tubelet 记录拒绝；dup 的二阶场景缓存仍按单帧重编码、报告无 `tubelet` 字段；pair 数据集配 dup 缓存（或反过来）读不进来。

## 6. 验收单

- C1 `git diff --stat 0d35288` 只有 §3 的文件；`src/` 没动；不带 `tubelet=pair` 时三个工具的编码输入和报告字段不变（S25a、S21b、C7 的已有测试照旧通过）。
- C2 三个工具在 pair 数据集上送进编码器的两帧与 §2 的表一致：时间顺序（前，后）、间隔正好 1 tick、每帧按自己的 tick 画。有没有哪一处把前一帧取成了同一帧、上一次观测、或真实轨迹上的帧。
- C3 探针和 floor 对真实轨迹的编码与 `encode_v7` 写缓存逐项相同（同一批 34 帧、同一个函数、同一个编码器类）；规划起点的两帧与缓存第 start 行同一个输入。

- C7 §5 的测试确实检查了声称的性质；`pytest tests/test_s25b2_online_pair.py` 全过。

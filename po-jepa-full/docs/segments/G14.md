# G14：双井“少动”原因分离实验 + 一致性权重缩放开关

2026-11-25 · 基于 full-model 1d74a80 · 分支 `seg/G14-shrinkage-isolation` · 任务条目 `GPU_TASKS.md` §8h

这份文件是本段的说明和验收单，审核 agent 按 §4 逐条核对。

## 1. 目标与范围

C-1/C-2 里 double_well 的 `po_jepa_full`（多段切分 + 零初始化 P_out）只预测出 no_cons 一半左右的运动、动作响应也小（G9、G12）。本段写一份 C-1 规模（200 条 × 2000 步，K = 16）的分离实验，回答：收缩是不是一致性项造成的、哪一项、是不是单种子现象、λ_t 调小能不能消除（导师 Tomas 2026-11-25 建议；Jerry 决策卡定**只缩 λ_t**，λ_s 保持标定值）。

为 λ_t 扫描加一个开关：`run.py --time-weight-scale {1,0.5,0.25}`（同时加了对称的 `--space-weight-scale`，本实验不用）。不做：不改任何损失、模型、标定算法；默认（不给开关或给 1）时协议、变体 dict、标定文件名、job.json、预登记逐键不变。

## 2. 定义（公式即实现）

- `checks.v7_variant()`：环境变量 `PO_JEPA_TIME_WEIGHT_SCALE` / `PO_JEPA_SPACE_WEIGHT_SCALE` ∈ {"1","0.5","0.25"}，不是 "1" 时以字符串进变体 dict（键 `time_weight_scale` / `space_weight_scale`）；其他值报错；v6 协议下设了报错。
- `checks.load_protocol()`：读到本变体的标定文件（`<数据集>-u<步数><切分/初始化/K 后缀>.yaml`，**不含**缩放后缀）且已标定时，loss.time_weight = cal.time_weight × s_t，loss.space_weight = cal.space_weight × s_s；系数是 2 的负幂，float64 乘法精确；s = 1 时原值不经乘法。
- 标签：`checks.weight_scale_suffix(variant)` = `~lt<s_t>`（s_t ≠ 1 时）+ `~ls<s_s>`（s_s ≠ 1 时）；`summarize_v7._variant_suffix` = 原后缀 + 这个后缀，缩放不同的任务不分到同一组。标定文件名（`variant_suffix`）不含缩放。
- 守卫：`workflow.write_v7_calibration` 在缩放下拒写（否则缩放后的 λ 会被当成同一变体的标定写回）；`run.py` 对 calibrate、sweep、calibrate-addon、check-addon 和 `po_jepa_full` / `po_jepa_time_only` / `po_jepa_space_only` 以外的条件拒收非 1 的缩放（其他条件的 λ 来自补跑标定或恒为 0）。
- 传递：`run.py` 把开关转成环境变量（和已设环境变量不同时报错，同 `--modes` 写法）；`v7jobs.with_variant` 和 `comparison` 的预登记已有的写法把变体（含缩放）写进 job.json / 预登记；`tools/plan_v7._job_env`（评测工具共用）按 job.json 设回两个缩放，缺省设回 "1"。

## 3. 实验（GPU_TASKS §8h）

29 条训练 + 66 条评测，见 §8h 的表。设计依据（CPU 实测，`tests/test_g14_weight_scale.py`）：两个权重都为 0 时，二等分和多段切分 JEPA 损失逐位相同、梯度只差 float32 舍入（相对差 0～2e-5；time_only 对照下 0.86），所以 no_cons 不分切分，只分初始化；`dyadic-zero` 的 no_cons 只作同设定的噪声参照。判定标准在项目文件夹 `small-validation-results/c1-isolation/2026-11-25_shrinkage-isolation-plan.md`。

## 4. 验收单

1. 默认不变：不设环境变量或设 "1" 时，`load_protocol()`、`v7_variant()`、`v7_calibration_path()` 与改前相同；job.json、预登记、`_loss_config` 快照不多键。
2. 缩放只乘在本变体标定值上，只改 time_weight / space_weight 两个数；标定文件名不变；缩放在 v6 下、非法值下报错。
3. 缩放进 job.json 的 variant；评测工具（`plan_v7._job_env`，state_readout、shrinkage_check 都用它）按 job.json 设回，默认任务显式设回 "1"，不受残留环境变量影响；读缩放任务时重建的 λ 与训练时相同，预登记比对能过。
4. 没有路径能把缩放后的 λ 写回标定文件，或让补跑标定、补跑条件静默用上缩放。
5. 汇总分组：`summarize_v7` 的标签带缩放后缀，和 `checks` 同一写法。
6. 任务文件（§8h 的 bash）：29 个训练格互不重复；输出目录名与 `weight_scale_suffix` 一致；X 段读 C-1 旧检查点用 `--cross-version`，新任务不用；探针、真值是 G12 在 200 条数据集上写的。
7. 测试的期望值是否独立，有没有写错实现测试照样通过的情况（故意改坏 14/14，脚本在项目文件夹 `small-validation-results/c1-isolation/scripts/mutate_g14.py`）。

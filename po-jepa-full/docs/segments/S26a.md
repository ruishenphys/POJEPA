## 3. 用法

```
python tools/make_v8_jobs.py --stage full  > jobs-v8-full.txt     # 先跑 A–C（D 段的 v7 条件可以同时跑）
python tools/make_v8_jobs.py --stage addon > jobs-v8-addon.txt    # 补跑标定、检查、训练+评测
python tools/make_v8_jobs.py --stage long --conditions po_jepa_full,matched_transformer,fixed_fourier,koopman > jobs-v8-long.txt
```

**v8 和 v7 场景上的补跑（make_addon_jobs.py）不能共用一份工作树**：基础标定文件 `configs/calibration/<场景>-<条数>-u<步数>.yaml` 和补跑标定 `configs/calibration/addon/…` 同名。混用时都会报错而不是静默用错：local 模式拒收导入的文件；v8 的 calibrate 覆盖导入文件后，v7 补跑的入口和训练任务按导入记录的 SHA 拒绝；导入工具遇到不同字节的目标文件拒绝。

## 4. Claude 定的（Jerry 可以改）

- 来源靠首行表头 + 不在导入记录里来认，不追溯到 calibrate 任务目录。
- addon 阶段的检查（AC2）沿用 v8 C2 的场景选法（第二个场景）。
- 二阶场景照 S25a 的规矩，要显式 `--scenes`。
- **koopman 不评空间采样**：它的 16×16 基底换网格时要求网格坐标等于 16→G 重采样的目标坐标（`koopman.grid_basis`），S25e 原生网格 12×12、20×20、24×24 是 `regular_grid(G, G)`，对不上（12×12 差 1e-16，20、24 边缘差 0.006–0.010），评测会报错，所以 `--stage space` 拒绝 koopman。08 §5.3 给 DROID 原生分辨率写过放宽规则（坐标对 `regular_grid` 核，基底仍是 R W），仿真要不要照用会改 koopman 在这些测试上的定义，留给 Jerry 定。fixed_fourier、transformer_consistency 在原生网格上能跑。

## 1. 目标与范围

- **M1（时间一致性多段切分）**：导师 2026-11-11 定方向，Jerry 2026-11-17 定抽法。把式 (ltime) 的二等分推广成引理 5.4 的 2^k 等分：
  L_time = E_{T,k}[ δ_h(Φ_T(Z), Φ_{Π_k}(Z)) / (c(Π_k)² + ε) ]，c(Π_k) = Σ_{i≥2} t_{i−1}τ_i = T²(1 − 2^{−k})/2。
  每个样本从 k ∈ {1, 2, 3} 里段长 T/2^k ≥ 0.25 周期的那些中均匀抽一个（T = 1 只有 k = 1, 2）。L_JEPA 不变，不加真值项，λ_t 按原规则重标定。
- **M2（P_out 零初始化）**：式 (residual_readout) Ẑ = Z + P_out(Ψ(C(τ) − C(0))) 不变，只把 P_out 权重初值清零，起点恰为 Φ_τ = Id。
- **C3（identity 退出对比，Jerry 2026-11-17）**：汇总的配对比较、对照列表、散点图不再把 identity 当基线；identity 照算，只作数值自检和归一化参照。
- **A 层**：方案 §5.1 的表逐行对到代码和测试，引理 5.3、5.4 和联合时空界在小模型上实测左边 ≤ 右边。

不做（第三段）：C-1/C-2 任务表、结果目录、summarize_addon 的变体分组（同一目录里混了两个变体会按重复任务报错，不会静默合并）；
DROID 配置不改（代码支持，DROID 的 LossConfig 默认二等分，DROID 的读出计数仍按二等分写死）。

`theory_bounds` 的常数按证明里实际用到的量在同一批上取上确界：
ε_t = max_{i≥2} ‖f_i − Φ_{τ_i}(f_{i−1}; u_i)‖ / (t_{i−1}τ_i)，L = max(0, max log(‖Φ_{τ_i}(f_{i−1}) − Φ_{τ_i}(p_{i−1})‖ / ‖f_{i−1} − p_{i−1}‖)/τ_i)，
ε_s、空间的 L 同理；联合界三次引理共用一组 ε_s、ε_t、L。所以“左边 ≤ 右边”检查的是实现和证明对象一致（组合路径、动作切法、范数、共用 s），
不是对训练好的模型给出新的经验结论。范数是 sqrt(δ_{h''}) = (N_{h''}E)^{−1/2} s^{−1}‖·‖_F，s 取起点 z，所有网格共用，差在 float64 里算。

## 4. 已知的取舍（审核时请判断）

1. k 用哈希抽而不是 torch generator：为了不改任何随机状态（查询序列、模型初始化、续训 RNG 都不动），且续训不用另存状态。哈希对 2、3 个选项的偏差 < 2^{−60}。
2. 混合 k 的批按 k 分组算组合支路：同组内逐位相同；和逐行单独算只差批大小带来的 float32 舍入（测试里约 1e-5 绝对误差，值量级 10）。
3. no_consistency、space_only 在多段切分变体下照样算时间项（权重 0，和 v7 的 zero_weight_still_runs_consistency_queries 一致），多花前向但数值和二等分变体相同。
4. `consistency_share` 监控的 step 取 completed − 1：调用点在更新之后，这样量的就是这一步训练用的那串 k。
5. 零初始化下 `train_step` 第 0 步只有 `p_out.weight` 有非零梯度（其余参数的梯度都经过 P_out 权重，恰为 0），一致性损失恰为 0；一步之后其余参数开始有梯度。早检（monitoring.early_check_updates）在一致性预热之后才看占比，零初始化会不会让占比偏低要等 C-1 的数据。

## 5. 验收单（审核 agent 逐条核）

1. 多段切分的组合支路是否就是式 (partition_rollout) 的 Φ_Π：段数、段长、动作切法、每段输入、梯度路径；direct 是否和二等分逐位相同、JEPA 项是否不变。
2. 分母 c(Π_k)² + ε 是否等于引理 5.4 的系数平方；k = 1 时是否和原式 (ltime) 逐位相同。
3. k 的抽法：均匀、只抽段长 ≥ 0.25 的 k、确定、不碰随机状态；训练、标定、监控三处是否用同一步序号（标定用批在查询序列里的序号）。
4. 读出计数和 Φ 次数核对（`_observed_update`、`expected_readouts`、`diagnostic_step`）在两种切分下都正确，二等分时和以前逐值相同。
5. 零初始化：随机数消耗不变、其余参数逐位相同、起点 Φ_τ = Id、只允许残差读出；标定在零一致性梯度时不除零。
6. 检查点和预登记：默认变体的 loss_config / model_config 快照格式和 job.json 字段与 863e3e1 相同（预登记的源码身份照常变化；跨版本只读评测走 addon/v7load）；非默认变体能被区分、不会误读。
7. 变体选择只在 v7 下生效；标定文件按变体分；rollout_sup 固定二等分。
8. C3：三个汇总工具的配对、对照列表、散点图里没有 identity；identity 的数值还在（数值自检一节、JSON）。
9. `theory_bounds` 的三个界和论文附录证明逐项一致（哪些量进 ε、L，求和下标 i≥2 / i≥1，T − t_i），没有把不等式写反或漏项。

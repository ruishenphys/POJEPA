## 1. 目标与范围

目标：`PO_JEPA_DATASET=<场景>~resolution=384:2000`（及 `zoom`、`pan`、`drift`，可与其他调节项、`horizon`、时间采样组合）经 `systems.get().frames()` 生成按新分辨率和相机画的画面，12 个场景都支持；物理、动作、隐藏状态与不带空间采样的同编号轨迹逐位相同；默认值（`resolution=256,zoom=1,pan=0,drift=0`）时生成的数据一个比特都不变，代码路径也不变（不经过 `timing`、`camera`）。

不做：编码、缓存、评测（`encode_v7.py`、`probe_actions.py`、`plan_v7.py` 遇到空间采样调节项直接报错，接入在第 6 阶段：V-JEPA 2 在 192/320/384 输入下的位置编码、特征网格 12/20/24 怎么进 16×16 的图谱模态）；放大（zoom > 1）和相机旋转。

## 2. 约定（Claude 定，Jerry 可以改）

1. **画布与相机**（`src/po_jepa/camera.py`）：“画布”是原来 256×256 画面的坐标系（画布像素，像素中心 k + 0.5），各场景世界坐标到画布的映射不变。相机是画布上一个轴对齐的正方形视野：边长 W = 256/zoom，输出 R×R（R = resolution），输出像素边长 s = W/R；视野中心 = (128, 128) + o(t)。输出像素 (i, j) 的中心在画布上 (top + (i+0.5)s, left + (j+0.5)s)，top/left = 128 + o − W/2。
2. **四个调节项**（`variants.py`，“空间”组）：
   - `resolution` ∈ {192, 256, 320, 384}（默认 256）：视野不变，只改像素数。
   - `zoom` ∈ [0.5, 1]（默认 1）：**只缩小**。放大会把画面边缘的物体切掉，违反 variants 里“除 occluders 外画面能看全状态”的约定。
   - `pan` ∈ [0, 1]（默认 0）：偏移半径 ρ = pan·S，S = (W − 256)/2 是缩小留出的余量；方向角 φ0 ~ U(0, 2π)（新随机流 12，每条轨迹不同）。|o| ≤ S，所以视野始终包含整块画布。pan > 0 要 zoom < 1。
   - `drift` ∈ [0, 0.5] rad/s（默认 0）：φ(t) = φ0 + drift·t·0.25 s，相机中心绕画布中心逆时针（世界 y 向上）匀速转，o_列 = ρ cos φ、o_行 = −ρ sin φ。drift > 0 要 pan > 0。选“绕中心匀速转”而不是线性漂移或随机游走：和 S21a 的会动干扰光点同一种设计，当前偏移（从画布在画面上的位置读出）决定下一帧的偏移，仍是一阶；线性漂移在长时程会出画布余量，随机游走一帧推不出下一帧。上限 0.5 rad/s（一圈 ≥ 12.6 s ≈ 50 tick）。
3. **画法：原生渲染**（不是把 256 的画面缩放过去）。各画图函数在 `systems.camera_view(view)` 里从 `systems.pixel_axes()` / `pixel_grid()` 取视野像素中心的画布坐标（默认就是 arange(256)+0.5，与原来的 meshgrid 逐位相同）：
   - 解析的形状（高斯光点、线段、圆盘、方块、push 的方块和推杆、landscape 的地形底图）在像素中心直接求值；抗锯齿的线性过渡宽度 e = max(1, s) 画布像素，写成 `clip(h + 0.5e − d, 0, e)/e`，e = 1 时与原式逐位相同。landscape 底图的归一化仍用画布 256×256 上的最小、最大值。
   - 背景纹理（grid、checker、noise 都是画布像素上的分段常数）、遮挡块、画布边：按输出像素足迹 [x − s/2, x + s/2]² 的面积精确平均（可分离的盒式滤波；网格线和棋盘用原函数，噪声块用重叠矩阵）。网格线 1 个画布像素宽，s > 1 时点采样会整条漏掉，所以必须面积平均。纹理在画布外周期延拓（最后被画布外的颜色盖住）。
   - 场：`advection_diffusion` 的 256 格浓度、`gray_scott` 的 128 格 U/V、`wave` 的 128 格位移，在格点中心之间周期双线性插值，再按原来的颜色映射上色。像素中心正好在格点中心时逐位等于格点值。
   - `gray_scott`、`wave` 的 1 像素宽高斯圆环标记：e > 1 时方差加 (e² − 1)/12、幅值乘 1/σ'（像素面积平均的高斯近似，积分不变）。光点（σ ≥ 3）不做这个修正。
   - 画布外：`camera.canvas_mask` 按画布覆盖比例与 SURROUND = (8, 10, 12) 混合（比所有背景都暗，完全在画布里的像素原样保留）。
4. **帧的生成走 `timing.frames`**（`Variant.resampled()` = 时间采样或空间采样起作用）：状态由 S24b 的主链 + 旁支给出（整 tick 时刻与原实现逐位相同，S24b B2 已核），每个取样时刻在它自己的相机视野里画（曝光窗口里 drift 的相机也在动），混 SURROUND，再曝光平均、加像素噪声、clip、取整。所以能和 `horizon`、`fps`、`jitter`、`exposure`、`switch_offset` 组合。
5. **像素噪声**：输出 R×R，整 tick 帧用流 4 按块 [R,R,3] 顺序抽（= 一次抽 [horizon+1,R,R,3] 的第 t 份；R = 256 时与原来逐位相同）；tick 内部的帧用流 11（S24b），形状 [R,R,3]。
6. **隐藏状态**不含相机偏移（相机只是观察方式）；诊断用 `camera.offsets(trajectory_id, times)`。

## 4. 验证

环境：Python 3.12.3、numpy 2.4.3、scipy 1.16.3、torch 2.11.0+cpu、PyYAML 6.0.3、h5py 3.15.1、opencv-python-headless 4.13.0.92、pytest 8.4.2（云端 `python3.12 -m venv`，依赖照 pyproject）。全部是 CPU 验证；没生成数据集规模的数据、没跑编码器。

### 4.1 单元测试

`tests/test_s24c_space.py` 111 个（参数化展开后），约 2.5 分钟，全过。关键对照是独立的：16 组画面哈希在 d7762a7（改写画图函数之前）上算好写死（`po-jepa-s24c/golden.py`），默认画法逐位相同；纹理、遮挡块、画布边与独立写的逐画布像素重叠矩阵对照；s = 1、整数平移的视野与原画面平移后逐位相同；偏移按独立构造的流 12 熵重算；光点质心和二阶矩与相机映射对照；像素噪声按一次抽 [33,R,R,3] 重算。

### 4.2 故意改坏

`po-jepa-s24c/mutations.py`（项目文件夹），41 处全部抓到（在单独拷贝的树里跑）。第一轮 40 处漏 9 处：2 处是等价改动（drift > 0 蕴含 zoom < 1；棋盘原函数取负时行列两个符号一起翻转），已换成非等价的；其余 7 处补了测试（整数平移视野、抗锯齿辅助函数、非单位视野下的观察调节项、默认画面哈希），并因此发现 `interval_cover` 的舍入问题（完全在画布内的像素被判成 1 − 1e-16 的部分覆盖），改成按端点比较直接取 1。结果 `mutations_result_round1.txt`、`mutations_result_round2.txt`。

### 4.3 全量回归

在 d7762a7 + 本段上：3027 过、141 跳过、4 失败，失败的是 `test_delivery` 里要 CUDA 13.0 的 4 个，基线上相同（约 20 分钟）。`tools/refresh_manifests.py` 重算清单后 SOURCE_MAP 0 个新候选；重算后 `test_delivery` 单独再跑一遍，仍只有这 4 个。

## 5. 遗留

- 编码、缓存、评测接空间采样：第 6 阶段。要定：V-JEPA 2 在 192/320/384 输入下的位置编码（3D-RoPE 能直接编码，但要核上游实现的插值）、12/20/24 特征网格怎么接 PO-JEPA 16×16 的图谱模态（论文的“跨网格一致”）；画布外的 SURROUND 区域在特征里怎么处理。
- 放大（zoom > 1）、相机旋转、透视：没做。
- 光点和细线是点采样，s 最大 2.7 画布像素时 σ = 3 的干扰光点只有约 1.1 个输出像素宽。

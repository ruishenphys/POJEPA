# S28d 多段切分变体下 po_jepa_rollout_sup 改成 2^k 段有真值滚动

2026-11-17 · 「完整模型下一轮小规模验证方案」§7 的 3b · 开工时 full-model 是 4c28063，PR #6（S28c，63aa50f）未合，本段叠在 63aa50f 上 · 分支 `seg/S28d-dyadic-rollout-sup`

这份文件是本段的说明和验收单，审核 agent 按 §5 逐条核对。设计文字在 `docs/design/08-conditions.md` §6.6、`16-sim-addon.md` §3.2 末尾。

## 1. 目标与范围

Jerry 2026-11-17 决策卡：多段切分（dyadic，M1）变体下，po_jepa_rollout_sup 也改成 2^k 段有真值滚动，和 po_jepa_full 的时间一致性用同一种切分（每个样本随机抽一个 k）。S28b 让 rollout_sup 所有入口固定二等分，本段撤掉这条。

改动范围：rollout_sup 的损失、单步、梯度范数（标定和监控）、`calibrate-addon` 的 λ_r 标定和补跑标定文件的读写核对、检查点标签；c2 任务文件和 `SMALL_VALIDATION_GUIDE.md` 里“等 Jerry 定”的提醒改成说明。

不做：默认变体（二等分）的任何数值或格式；中间时刻的真值监督；Transformer、DROID；C-1/C-2 的阈值和汇总规则。

## 2. 定义（开工时写定，对齐 S27a 两段版和 M1）

| 项 | 定义 | 来源 |
|---|---|---|
| k | k_b = `losses.dyadic_levels(T_b, sample_ids, step)`：k ∈ {1,2,3} 里段长 T/2^k ≥ 0.25 周期的那些中均匀抽一个，SHA256 哈希，不碰随机状态 | M1（S28b），和 po_jepa_full 同一函数同一步序号，所以同一步同一批 k 逐行相同 |
| 步序号 | 训练 completed_steps；标定用批在查询序列里的序号；监控 completed − 1 | 和 S28b 三处相同 |
| 滚动路径 | Φ_Π(Z; u) = `losses.partition_predictions(...).composed`：2^k 段、h = T/2^k、第 i 段动作是原控制 [i·h, (i+1)·h) 的精确交集、每段输入是上一段的 raw 输出，不 LN、不 detach | 引理 5.4 的 Φ_{Π_k}，和 po_jepa_full 的组合支路逐位相同 |
| JEPA 项 | 仍是长支 direct 对 Z_target(T)，和二等分逐位相同 | M1：L_JEPA 不变 |
| 真值目标 | 只有终点 Z_target(T)（同一个 `batch.raw_target`）；中间各段终点不监督 | S27a：两段版也不监督 τ 时刻，训练批里没有中间真值帧 |
| 距离 | L_roll = mean_B mean_(N,E) \|LN(Φ_Π(Z; u)) − LN(Z_target(T))\|，`losses.jepa_distance`（无 affine LN、eps 1e-5、p = 1、标签停梯度） | S27a（Jerry 11-12 选 A） |
| 归一化 | 不除 c(Π_k)² = (T²(1 − 2^{−k})/2)²，不按 k 加权，样本等权 | S27a 不除 (τσ)² 的同一理由：分母配的是组合缺口随段长消失，真值误差不随它消失 |
| k = 1 | 和两段版逐位相同（两段版是 k = 1 的特例） | S28b `test_k1_partition_is_bitwise_the_bisection_loss` |
| 总损失 | L = L_JEPA + w(s)(λ_r L_roll + λ_s L_space)，λ_s 沿用基础标定 | S27a |
| λ_r | ρ·median\|∇L_JEPA\| / median\|∇L_roll\|，JEPA-only 预训练跟变体走（po_jepa_no_consistency，和同一变体的 `run.py calibrate` 相同） | 16 §3.2 |

## 3. 改动

| 位置 | 改动 |
|---|---|
| `src/po_jepa/rollout_supervision.py` | 新 `rollout_predictions(model, …, config, step, sample_ids)`：二等分走 `losses.temporal_predictions`（S27a 原样），多段切分走 `dyadic_levels` + `losses.partition_predictions`；`rollout_supervision_loss` 收 `TemporalPredictions` 或 `PartitionPredictions`，只用 composed，不读时长和 k |
| `runtime/addon/conditions.py` | `build` 不再强制二等分；`rollout_sup_step` 用 `rollout_predictions(step=completed_steps)`；`consistency_share` 给 rollout_sup 传 step = completed − 1；去掉不再用的 `po_temporal_predictions` 导入 |
| `runtime/addon/calibration.py` | `rollout_gradient_norms(…, step=None)` 用 `rollout_predictions`；补跑标定读取：`~dyadic` 变体的 po_jepa_rollout_sup 一项必须有 `rollout_partition: dyadic`（`entry_keys`），缺了按“S28d 以前的代码标的”报错，值不等于协议切分也报错；二等分变体格式不变、带这个键反而拒绝 |
| `runtime/addon/calibrate.py` | `_jepa_only` 不再强制二等分；`_gradient_norms` 给 rollout_sup 传 step；`calibrate_addon` 在多段切分时给 rollout_sup 一项写 `rollout_partition` |
| `runtime/training.py` | `_loss_config` 不再拒绝 dyadic 的 rollout_sup；切分照样进快照（检查点标签） |
| `tools/make_small_validation_jobs.py`、`SMALL_VALIDATION_GUIDE.md` | c2 多段切分变体开头的提醒改成说明（2^k 段、同一串 k、旧标定文件会被拒） |
| 测试 | 新 `tests/test_s28d_dyadic_rollout_sup.py` 16 个；`test_s28b_dyadic_zero_init.py` 两个断言旧行为（固定二等分）的测试改成新行为；`test_rollout_sup.py` 一条报错文案 |

读出计数不用改：`expected_readouts` 对 PO 类（含 rollout_sup）本来就是 (temporal_phi_calls + 2) × readouts_per_phi，S28b 时 rollout_sup 固定二等分所以恒为 10，现在随 k 变，和实际 Φ 次数一致（新测试 `test_observed_update_readouts_under_dyadic`）。

## 4. 取舍（审核时请判断）

1. 只监督终点、不监督中间段终点：和 S27a 一致，也因为训练批里没有中间时刻真值。代价是 k 大时中间状态只靠终点误差约束。
2. 不除 c(Π_k)²、不按 k 加权：不同 k 的 L_roll 量级可能不同（段数多误差积累多），均匀抽 k 时期望里各 k 等权。λ_r 用同一串 k 标定，所以平均尺度已被 λ_r 吸收。
3. 标定文件加 `rollout_partition` 键而不是改文件名：文件名已按变体分（`~dyadic`），加键只为拒用 S28d 以前的代码在多段切分下标的旧 λ_r（c2 任务表以前就会排这种标定）。
4. 混合 k 的 CPU 反传在多线程下不逐位可复现（同一函数连算两次，omega_head 梯度差到 1e-3 量级，是 PyTorch CPU 线程舍入，不是本段代码）；两个梯度核对测试设单线程后用紧容差。

## 5. 验收单（审核 agent 逐条核）

1. 多段切分变体下 rollout_sup 的 k 是否和 po_jepa_full 同一函数、同一步序号（训练、标定、监控三处）。
2. 滚动路径是否就是 `partition_predictions` 的 composed（引理 5.4 的 Φ_{Π_k}），梯度经全部段传回，真值停梯度；JEPA 项是否仍在 direct 上、不变。
3. L_roll 是否只比终点真值、用 JEPA 距离、不除 c(Π_k)²、不按 k 加权；k = 1 是否和两段版逐位相同。
4. 二等分变体：rollout_sup 的数值、Φ 次数、检查点快照、补跑标定文件格式是否和 S27a/S28b 逐位相同。
5. λ_r 标定：预训练和量梯度是否都用本变体的切分；`rollout_partition` 的写入、读取和拒用规则有没有漏洞（旧文件、错值、二等分文件带键、其他条件带键）。
6. 检查点：dyadic 的 rollout_sup 与二等分的 rollout_sup、与 po_jepa_full 是否互相读不进来。
7. 读出计数 `expected_readouts` / `observed_update` 在两种切分下是否正确。

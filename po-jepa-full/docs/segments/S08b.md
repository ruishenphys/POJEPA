## 3. 自己定的（Jerry 可以改，不改口径）

1. **官方规模的判断**：`load_official` 和 bf16 autocast 原来比 `spec == OFFICIAL`，加字段后改成比结构字段（encoder_dim、width、depth、heads、mlp_ratio）。v7 时两种判断结果相同。
2. **7 维前向多一条检查**：控制通道数必须等于 `spec.action_dim`（v7 时总成立，不改数）。
3. **物理动作在 float64 上算**：`physical_tick_actions` = `tick_actions`（float32 模型单位的时间平均）转 CPU float64 后 × scale + offset；状态积分用这份 float64，动作 token 转模型精度。DROID 的 offset 是 0。
4. **绑定包装的起点**：τ 离整数 ≤ 1e-9 个周期就取整（物理秒相减的舍入）；τ < 0 或 > 窗口时长报错；控制单位、来源编号必须和 `reference` 相同。同一步上要积分的样本一起调 `compute_new_pose`（逐行独立，和逐个调用逐位相同，测试按逐个手调核）。
5. **`ac_steps` 在 learned_constant 模式下忽略起点状态**（S11b 的评测代码总是传状态）。
6. **`cpu_threads` 的份数**：`GraphSpectrum.eig_threads`，不设时取 `os.cpu_count()`；S09 的工厂按 `resources.train.cpus` 设。`cuda_float64` 要求模型在 CUDA 上，否则报错。
7. **官方 train.py 参照**：两项损失逐位相同，更新后的参数除 `predictor_embed.bias` 外逐位相同。这一项的梯度是对全部 token 求和，官方先把各帧摊平成 [B, T·N, E] 再过 Linear，v7 包装按 [B, T, N, E] 过，求和顺序不同，梯度相对差约 1.5e-7（只这一项）。改成摊平会动 v7 的数，所以不改，测试对这一项用 1e-9 的绝对容差。

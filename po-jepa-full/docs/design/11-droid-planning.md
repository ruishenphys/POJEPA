# 11 DROID 离线规划

2026-11-08 · 第一版

DROID 没有模拟器，没法真的执行规划出来的动作，所以只做两种离线检验：给定起点和真实的未来帧，(1) 真实动作在 64 个候选里排第几；(2) CEM 从零开始搜出的动作，和真实动作的净位移差多少。两项都在每个评测任务里做（10 §8.1），代码在 `src/po_jepa/droid/planning.py`（S12）。

## 1. 共同部分

- 窗口：每个测试集的附加回合（前 200 条，06 §3）里 d ∈ {1, 4} 的冻结窗口。排名用全部这些窗口；CEM 每条回合、每个 d 只用排在第 1 的那个窗口。
- 代价：c(a) = d(Φ_d(z; a), z*_d)，d 是 JEPA 距离（mean |LN(·) − LN(·)|，逐样本），16×16 网格，z*_d 是真实的未来帧特征（目标图像）。所有条件用同一个代价。
- 动作单位：候选和搜索都在模型单位（物理值 / 尺度，01 §5.3）里做，组装成 `ActionSegments` 的方式和 06 §4 相同（每个周期一段）。AC 在包装层乘回物理单位，状态从窗口起点的真实状态出发按候选动作积分（09 §6.2）。
- identity 不看动作，所有候选的代价相同。下面的平局规则保证它正好得到随机水平，用来核对实现。

## 2. 动作排名

- 候选：窗口 w 的真实动作，加上它的 63 个干扰项窗口（06 §3）的动作，共 64 个。干扰项来自同一测试集、同一时长、别的回合，只借用它们的动作，起点和目标仍是 w 的。
- 每个候选算一次代价（64 个候选正好一批）。
- 真实动作的名次：r_lo = 1 + #{代价严格更小的候选}，t = #{代价相等的其他候选}，r_hi = r_lo + t。平局按随机打破取期望：
  - 平均名次 = (r_lo + r_hi) / 2；
  - 第一名的比例 = 1/(t + 1)（r_lo = 1 时），否则 0；
  - 倒数名次的期望 = mean_{r = r_lo…r_hi} 1/r。
  “相等”指 float32 代价逐位相等。
- 报告：每个测试集、每个 d 上这三项的回合宏平均（先在回合内平均），以及随机水平（平均名次 32.5、第一名 1/64、倒数名次的期望 H_64/64 ≈ 0.0741）。

## 3. CEM

- 搜索变量：每个周期的位置 3 维和夹爪 1 维，共 4d 维（模型单位）。旋转 3 维固定为真实执行的值：从单帧目标图像里很难辨认小角度转动，固定后搜索空间小、各条件之间可比；论文里写明这一点。
- 参数取自配置 `evaluation.cem`：4 轮，每轮 256 个样本，取代价最小的 24 个为精英；初始均值 0、标准差 0.5；每个样本截到 [−1.5, 1.5]。
- 更新：μ ← 精英的均值，σ ← 精英的标准差 + 1e-3（和 v7 `plan_v7.py` 相同）。排序用 `numpy.argsort(kind="stable")`，平局取序号小的。最后返回 μ。
- 随机数：每个窗口一个 `numpy.random.default_rng(seed)`，seed = `int(sha256(f"{window_salt}|cem|{w.id}").hexdigest()[:16], 16)`。所有条件在同一窗口上用同一串噪声（共同随机数），条件之间的差别只来自代价。
- 指标（物理单位，乘回尺度后算）：
  - 净位移误差 = ‖Σ_j p̂_j − Σ_j p_j‖₂（米），p_j 是第 j 个周期的位置动作，p̂ 是 CEM 的结果；
  - 夹爪误差 = |Σ_j ĝ_j − Σ_j g_j|；
  - 不动的参照：同样的两个量取 p̂ = ĝ = 0，即真实净位移 ‖Σ_j p_j‖₂ 和 |Σ_j g_j|；
  - 相对误差 = 误差 / max(不动时的误差, 1e-9)。
- 报告：每个测试集、每个 d 上净位移误差、夹爪误差、相对误差的回合宏平均和中位数；另报真实净位移小于 1 cm 的窗口数（这些窗口上相对误差没有意义，汇总时单独列出，不进相对误差的平均）。

## 4. 输出

`eval/<条件>/seed<种子>/<测试集>/planning/`：

- `rank.json`：每个窗口的 64 个代价、真实动作的 r_lo、t 和三项名次指标；
- `cem.json`：每个窗口每轮的 μ、σ、精英代价，最终动作，四个误差量；
- `report.json`：§2、§3 的汇总。

## 5. 成本

排名每个窗口 64 次前向（一批）；每个测试集约 1,600 个窗口。CEM 每个窗口 4 × 256 = 1,024 次前向，每个测试集 400 个窗口。官方规模 AC 在 d = 4 时每次前向要自回归 4 步，是最慢的条件，以试跑实测为准。

## 6. 测试（CPU，S12）

- identity：每个窗口都是 64 个候选全部相等，平均名次正好 32.5、第一名比例 1/64、倒数名次的期望等于 H_64/64。
- 用一个“代价 = 动作和真实动作的距离”的玩具模型：真实动作名次为 1；CEM 的净位移误差随轮数单调不增。
- 同一窗口、同一 seed，两次运行的 CEM 结果逐位相同；换条件时噪声相同。
- 旋转维在 CEM 的全部样本里都等于真实值。
- AC：用小规格假模型核对候选动作乘回尺度后进模型、状态按动作积分。

## 7. S12 实现补注（2026-11-10）

代码 `src/po_jepa/droid/planning.py`，测试 `tests/test_droid_planning.py`，说明和验收单 `docs/segments/S12.md`。实现时定的几条（不改上面的口径）：

- §2 的随机水平原写 ≈ 0.0745，实际 H_64/64 = 4.7439/64 ≈ 0.0741，已改；报告里的随机水平由代码按 K 算。
- CEM 的样本截断区间 = [−clip, clip] 与物理界换算到模型单位的区间的交集。尺度 ≤ 物理界 / 1.5 时（位置尺度厘米级、夹爪尺度 ≤ 2/3）就是 [−1.5, 1.5]，否则 `from_physical_segments` 会因越界报错。
- 相对误差：逐窗口记位置和夹爪两种，报告里的“相对误差”只取位置（真实净位移 < 1 cm 的窗口不进平均，§3）。
- `commanded` 配置：窗口本身或任一干扰项的回合没通过时跳过这个排名窗口（候选数始终 64），计数写进报告。
- §6 的“净位移误差随轮数单调不增”：玩具代价是逐周期的动作距离，d = 1 时逐窗口成立；d = 4 时净位移是 4 个周期之和，个别窗口中间一轮会变大（合成数据 17 个窗口里 1 个），测试改为逐窗口“最后小于不动”加回合平均逐轮单调不增。
- AC：规划代码只收一个可选的 `bind(model, start_state, reference)`（09 §6.2，`droid.ac.bind` 在 S08b 写），每批候选用窗口 w 的起点状态和这批候选自己的控制绑定一次。

# 15 开发流程

## 1. 循环

每段走同一个循环，三个各自独立的 agent 加 Codex：

1. **提示词 agent** 读设计规格、主干上的最新代码和上游段的接口，写 `docs/segments/Sxx.md`：目标、要读的文件、接口签名和数据格式、不能动的地方、要写的测试、逐条可检查的验收标准（取自 14 §3）、不做什么。
2. **编写 agent** 在 `seg/Sxx-名字` 分支上实现，跑本段测试和全部回归测试，提交并开 PR 到 `full-model`。
3. **审核 agent** 只拿到本段的验收单和 PR 的改动，不看编写过程。逐条核对验收标准、跑测试，重点找会导致返工的问题：接口和数据格式、公式和单位、对 v7 行为的影响。结论只有“通过”或“不通过”；不通过的每一条写明文件和行号、对应的验收标准、复现命令。不提风格意见。
4. **Codex** 在 GitHub 的 PR 上独立审同一份改动。需要 Jerry 在 Codex 设置里给 ruishenphys/POJEPA 打开自动代码审核；意见回到我这边，由我转给编写 agent。

- 一段在审核时，提示词 agent 写下一段的提示词，编写 agent 可以写另一条线上的段。
- 审核不通过：编写 agent 按定位到的问题修改，审核只复审改动的部分。
- 合并条件：审核 agent 和 Codex 都通过、测试全绿，我用 squash 合并进 `full-model`，主干每一步都能跑。
- 防止堆积：同时最多 2 段在审核中；修改优先于开新段；同一段连续两次不通过，我先停下来查是不是提示词或规格的问题。
- 写代码时发现规格有问题：先改规格（单独提交，说明原因），再改代码；影响论文或实验设计的改动先问 Jerry。

|---|---|---|---|

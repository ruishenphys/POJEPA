# 03 DROID 下载

2026-11-08 · 第一版

阶段 2：按片下载每条回合的 `trajectory.h5` 和左外部相机 MP4（元数据在阶段 1 已经下好）。每片一个 CPU 任务 `download/<片名>`，要联网。代码在 `src/po_jepa/droid/download.py`（S04）。

## 1. 下载哪些

一个配置下载：用到的训练片（02 §6）加 `val`、`id_test`、`ood_test`。正式运行 20 + 3 = 23 片，约 2.15 万条、380 GB。

每条回合两个文件：

| 文件 | 对象名 | 本地路径 |
|---|---|---|
| 轨迹 | `{data.prefix}<h5>`（02 §3 的 `h5` 字段） | `raw/<片名>/<uuid>/trajectory.h5` |
| 视频 | `{data.prefix}<left_mp4>` | `raw/<片名>/<uuid>/<left_serial>.mp4` |

另外把 `metadata.jsonl` 里这一条的官方元数据（去掉 `_` 开头的三个字段）按原键顺序写成 `raw/<片名>/<uuid>/metadata.json`，供人查看。

## 2. 每个文件怎么下

1. 先用 JSON API 取对象的大小和 MD5：`GET {data.list_api}/<URL 编码的对象名>?fields=size,md5Hash`（重试规则同 02 §1）。
2. 下载到 `<目标>.part`（`{data.object_base}` 后接相对路径，流式写，每块 8 MB）。
3. 大小和 MD5 都对，才把 `.part` 改名成目标文件；不对就删掉 `.part` 重下，最多 3 次，仍不对就让任务失败并在报错里写明对象名。
4. 启动时遇到残留的 `.part`，直接删掉重下（单个文件最大几十 MB，不做断点续传）。

一条回合两个文件都到位后写 `raw/<片名>/<uuid>/DOWNLOADED.json`：两个文件的对象名、大小、MD5（base64，和 GCS 一致）、本地 SHA-256、下载时间。重跑时有 `DOWNLOADED.json` 且两个文件的大小一致，就跳过这条（不重算 MD5，避免每次重读 380 GB）；有 `RAW_DELETED.json`（§4）的回合也跳过，不重新下载。

一片里 16 条回合并行下载。

## 3. 片完成

全部回合都有 `DOWNLOADED.json` 后，写片完成记录 `raw/<片名>/_complete/<配置名>.json`：配置 SHA、这一片在该配置下的 uuid 列表、每条 `DOWNLOADED.json` 的 SHA。任务以这个文件为完成标志。

- 同一片在别的配置下已完成（例如试跑做过 `train-000` 的前 500 条），正式运行只补没下的回合。
- 回合在存储桶里不存在或反复校验失败：任务失败，不跳过。划分已经冻结，不能悄悄少一条；出现这种情况由我先查原因再定。
- 存储桶里缺 h5 或左相机 MP4 的回合已在索引阶段按 `missing_raw` 剔除（02 §4，S03b），不会进划分；下载时遇到 404 仍是失败（说明存储桶在索引之后变了）。

## 4. 删原始文件

一片的特征编码完成、清单核对通过之后（05 §3），`encode/<片名>` 任务带 `--delete-raw` 时删掉这片的 MP4 和 h5，保留 `metadata.json` 和 `DOWNLOADED.json`，并在每条回合目录里写 `RAW_DELETED.json`（删除时间、这条回合特征 JSON 的 SHA）。试跑删掉的 `train-000` 前 500 条，正式运行时不会被重新下载，准备和编码也因为输出已在而跳过。只对训练片这样做；`val`、`id_test`、`ood_test` 三片（约 1,300 条、20 多 GB）一直保留，因为测试附加编码（05 §4）和以后的核对要用。同时占用的原始文件约 100 GB。准备检查没通过、没编码的回合不删（S06a 定，留着查原因）。

以后需要时按索引重新下载，`DOWNLOADED.json` 里的 MD5 保证下到的是同一份文件。

## 5. 测试用的假服务器

S04 的测试在本机起一个只服务临时目录的 HTTP 服务器，模拟两个接口（对象元数据、对象内容），可以按测试需要返回错误的内容、截断的内容、500 错误和 404。下载代码的两个地址前缀都从配置读，测试时换成本地地址。
